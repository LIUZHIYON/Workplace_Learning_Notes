# Tutorial 13: Zero-copy access to the blackboard 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-advanced/tutorial_13_blackboard_reference
> 说明：之前黑版传数据都是**拷贝（值语义）**。但如果对象很大（比如点云数据），每次拷贝性能受不了。这篇教你**零拷贝（引用语义）**——直接操作黑版里存的那个对象。

---

## 一、问题背景

**原文大意：**
> 之前的 `getInput` 和 `setOutput` 都是**值语义**——拷贝一份数据。对于大型数据结构（点云、图像），每次都拷贝代价很大。有些对象甚至无法拷贝（non-copyable）。
> 
> 这时候需要用**引用语义**——直接访问黑版里存的对象。

**我的解释：**

```
值语义（之前的方式）：
  getInput<T>("port") → 从黑版拷贝一份到本地

引用语义（这篇教的）：
  直接拿指针/引用操作黑版里的原始对象 → 零拷贝
```

**适用场景：**

| 场景 | 用值语义？ | 用引用？ |
|---|---|---|
| int、double、小结构体 | ✅ 没问题 | ❌ 没必要 |
| 大型点云（Pointcloud） | ❌ 太慢 | ✅ |
| 图像帧 | ❌ 太慢 | ✅ |
| non-copyable 对象 | ❌ 编译报错 | ✅ |

---

## 二、方法 1：用 `shared_ptr<T>` 做端口类型

**原文思路：**
> 端口类型不要用 `Pointcloud`，用 `std::shared_ptr<Pointcloud>`。拷贝 shared_ptr 只复制指针，不复制底层数据。

**端口声明：**

```cpp
// 写入端：
PortsList AcquirePointCloud::providedPorts()
{
    return { OutputPort<std::shared_ptr<Pointcloud>>("cloud") };
}

// 读取端：
PortsList SegmentObject::providedPorts()
{
    return {
        InputPort<std::string>("obj_name"),
        InputPort<std::shared_ptr<Pointcloud>>("cloud"),
        OutputPort<Pose3D>("obj_pose")
    };
}
```

**使用方式（跟普通端口一样）：**

```cpp
// AcquirePointCloud
std::shared_ptr<Pointcloud> my_cloud = std::make_shared<Pointcloud>();
// ... 填充点云数据 ...
setOutput("cloud", my_cloud);  // 只拷贝 shared_ptr，不拷贝点云数据本身

// SegmentObject
auto cloud = getInput<std::shared_ptr<Pointcloud>>("cloud");
// cloud 是个 shared_ptr，跟黑版里的是同一个底层对象
```

**⚠️ 问题：线程不安全**

> 如果节点有自己单独的线程（比如异步 Action），多个线程可能同时访问同一个 `Pointcloud` 对象，导致**数据竞争**。

## 三、方法 2：`getLockedPortContent` + `castPtr`（推荐）

**原文：**
> 从 BT.CPP 4.5.1 开始推荐用这个方式——自带**互斥锁**，线程安全，而且端口类型用原始类型，不需要包一层 shared_ptr。

**端口声明——直接用原始类型，不用 shared_ptr：**

```cpp
PortsList AcquirePointCloud::providedPorts()
{
    return { OutputPort<Pointcloud>("cloud") };     // 注意：是 Pointcloud 不是 shared_ptr<Pointcloud>
}

PortsList SegmentObject::providedPorts()
{
    return {
        InputPort<std::string>("obj_name"),
        InputPort<Pointcloud>("cloud"),              // 也是原始类型
        OutputPort<Pose3D>("obj_pose")
    };
}
```

**访问方式——用 `getLockedPortContent` + `castPtr`：**

```cpp
// 获取锁住的端口内容
if (auto any_locked = getLockedPortContent("cloud"))
{
    // any_locked 存在期间，互斥锁保持锁定

    if (any_locked->empty())
    {
        // 黑版还没初始化 → 用 assign 初始化
        any_locked.assign(my_initial_pointcloud);
    }
    else if (Pointcloud* cloud_ptr = any_locked->castPtr<Pointcloud>())
    {
        // 转型成功 → 通过 cloud_ptr 直接操作黑版里的 Pointcloud
        // 不需要拷贝！
        cloud_ptr->filter();
        cloud_ptr->downsample(0.01);
    }
    // 离开作用域 → any_locked 析构 → 互斥锁释放
}
```

**关键 API：**

| API | 作用 |
|---|---|
| `getLockedPortContent("port_name")` | 返回一个锁住的对象包装器（`LockedPtr`） |
| `.empty()` | 检查黑版里是否还没有值 |
| `.assign(value)` | 初始化黑版里的值 |
| `.castPtr<T>()` | 转型到 `T*` 直接操作 |
| `any_locked` 析构时 | 自动释放互斥锁 |

---

## 四、两种方法对比

| 维度 | 方法 1：shared_ptr | 方法 2：castPtr |
|---|---|---|
| 端口类型 | `shared_ptr<T>` | `T`（原始类型） |
| 拷贝开销 | **小**（只拷贝指针） | **零**（直接操作原始对象） |
| 线程安全 | ❌ **不安全** | ✅ **有互斥锁保护** |
| API 复杂度 | 简单，跟普通端口一样 | 需要 `getLockedPortContent` + `castPtr` |
| 推荐版本 | 旧版本兼容 | 4.5.1+ 推荐 |
| 推荐度 | 简单场景可用 | **推荐** |

---

## 五、什么时候用哪个

```cpp
// 小数据 → 用值语义，简单
InputPort<int>("count");
InputPort<std::string>("name");
InputPort<Pose2D>("pose");      // 几个 double，不贵

// 大数据且只有一个线程访问 → 用 shared_ptr，简单
OutputPort<shared_ptr<Pointcloud>>("cloud");

// 大数据且多线程访问 → 用 castPtr
InputPort<Pointcloud>("cloud");
// 在 tick 里用 getLockedPortContent + castPtr 访问
```

---

**一句话总结：**
> 大对象用引用语义避免拷贝。方法 2（`getLockedPortContent` + `castPtr`）是官方推荐的线程安全方案，端口类型直接写原始类型，通过指针零拷贝访问黑版里的数据。
