# Migration from BT.CPP 3.x 逐段解释

> 来源：https://behaviortree.dev/docs/migration
> 说明：这是官网文档的**最后一篇**（补遗）。如果你从 BT.CPP 3.x 迁移到 4.x，这篇列出了所有你需要知道的改动。**如果你直接学的是 4.x，这篇可以跳过不看。**

---

## 一、官方指南说明

**原文：**
> 4.X 的大部分改动是增量式的，向后兼容。仓库里有一个 `convert_v3_to_v4.py` 脚本可以帮你自动转换（但记得检查结果）。

---

## 二、类名变更

| 3.8 的名字 | 4.x 的名字 | 在哪用 |
|---|---|---|
| `NodeConfiguration` | `NodeConfig` | C++ |
| `SequenceStar` | `SequenceWithMemory` | C++ 和 XML |
| `AsyncActionNode` | `ThreadedAction` | C++ |
| `Optional` | `Expected` | C++ |

**快速兼容（临时方案）：**

```cpp
namespace BT {
  using NodeConfiguration = NodeConfig;
  using AsyncActionNode = ThreadedAction;
  using Optional = Expected;
}
```

---

## 三、XML 根标签变更

**3.x：**
```xml
<root>
```

**4.x：**
```xml
<root BTCPP_format="4">
```

加 `BTCPP_format="4"` 属性，这样才能兼容两个版本。

---

## 四、SubTree 和 SubTreePlus

| 3.8 | 4.x |
|---|---|
| `<SubTree>` | **弃用**（Deprecated） |
| `<SubTreePlus>` | 改为 `<SubTree>`（新版默认） |

4.x 里的 `SubTree` 默认带端口 remap（等价于旧版的 SubTreePlus）。

---

## 五、SetBlackboard 和 BlackboardCheck → 脚本语言

**3.x 的旧方式（啰嗦）：**

```xml
<SetBlackboard output_key="port_A" value="42"/>
<SetBlackboard output_key="port_B" value="69"/>
<BlackboardCheckInt value_A="{port_A}" value_B="{port_B}"
                    return_on_mismatch="FAILURE">
    <MyAction/>
</BlackboardCheckInt>
```

**4.x 的新方式（简洁）：**

```xml
<Script code="port_A:=42; port_B:=69"/>
<MyAction _failureIf="port_A!=port_B"/>
```

对比：旧版用了 3 个节点 + 1 个包装 decorator，新版用了 2 行属性。

---

## 六、主循环 Tick 方式变更

**3.x 的旧方式（`tickRoot()` 已移除）：**

```cpp
while (status != NodeStatus::SUCCESS || status == NodeStatus::FAILURE) {
  status = tree.tickRoot();               // ❌ 已移除
  std::this_thread::sleep_for(sleep_ms);
}
```

**4.x 的新方式（推荐）：**

```cpp
// 方式 1：手动循环
while (!BT::isStatusCompleted(status)) {
  status = tree.tickOnce();
  tree.sleep(sleep_ms);    // 可被 emitWakeUpSignal 中断
}

// 方式 2：内置循环（最推荐）
status = tree.tickWhileRunning(sleep_ms);
```

**关键区别：**
- `tree.sleep()` 是**可中断的**——任何节点调用 `emitWakeUpSignal()` 可以立即唤醒
- `tickWhileRunning()` 自带内部循环，一行搞定

---

## 七、新增 SKIPPED 状态

**原文：**
> 当 `PreCondition` 不满足时，节点会返回 `SKIPPED`，表示"我被跳过了，没有实际执行"。

**重要规则：**
- **叶子节点**不需要返回 `SKIPPED`（这是 precondition 的事）
- **ControlNode 和 Decorator** 必须处理这个新状态——如果子节点返回 SKIPPED，应该继续执行下一个子节点

---

## 八、异步控制节点（AsyncSequence / AsyncFallback）

**3.x 存在的问题：**
> 如果 Sequence 的所有子节点都是同步的，整个 Sequence 就变成了"原子操作"——`ReactiveSequence` 里的条件在 Sequence 执行期间没法打断它。

```xml
<ReactiveSequence>
    <AbortCondition/>
    <Sequence>
        <SyncActionA/>
        <SyncActionB/>
        <SyncActionC/>
    </Sequence>
</ReactiveSequence>
<!-- 一旦 Sequence 开始跑，AbortCondition 永远打断不了 -->
```

**4.x 的解决：** 引入 `AsyncSequence` 和 `AsyncFallback` ——每个同步子节点执行完后返回 RUNNING，让出执行权。

```xml
<ReactiveSequence>
    <AbortCondition/>
    <AsyncSequence>
        <SyncActionA/>          <!-- 执行完返回 RUNNING，让条件重新检查 -->
        <SyncActionB/>          <!-- 同上 -->
        <SyncActionC/>          <!-- 同上 -->
    </AsyncSequence>
</ReactiveSequence>
```

---

## 九、迁移检查清单

| 需要改的地方 | 怎么做 |
|---|---|
| C++ 类名 | `NodeConfig`、`ThreadedAction`、`Expected` |
| XML 根标签 | 加 `BTCPP_format="4"` |
| XML 节点名 | `<SubTreePlus>` → `<SubTree>`、`<SequenceStar>` → `<SequenceWithMemory>` |
| SetBlackboard | 替换为 `<Script>` |
| BlackboardCheck | 替换为 `_failureIf` / `_skipIf` |
| 主循环 | `tickRoot()` → `tickWhileRunning()` |
| 处理 SKIPPED | ControlNode/Decorator 需要支持新状态 |

---

**一句话总结：**
> 如果直接从 4.x 学起，这篇可以跳过——你学的本身就是新 API。核心变化是：改名、简化脚本、新的中断式 ticks 和 SKIPPED 状态。
