# Ports VS Blackboard Guide 逐段解释

> 来源：https://behaviortree.dev/docs/guides/ports_vs_blackboard
> 说明：Guides 系列最后一篇，也是**最重要的设计哲学**之一——为什么永远不要直接访问黑版，而是应该始终通过端口。

---

## 一、引言

**原文大意：**
> BT.CPP 是（据我们所知）唯一一个引入了 **Input/Output Port（输入/输出端口）** 概念的行为树实现。
>
> 端口是黑版之上的一个**间接层**，增加了额外的语义信息。
>
> 理解为什么**推荐用端口**、**不推荐直接用黑版**，是理解 BT.CPP 设计哲学的关键。

---

## 二、BT.CPP 的设计目标

### 2.1 模型驱动开发（Model Driven Development）

**原文的两个图对比了有没有端口的区别：**

**没有端口——数据流不可见：**

```
[Node A]  ←→  [Node B]
（你只能通过读代码或文档才能知道它们之间传了什么数据）
```

**有端口——数据流是模型的一部分：**

```
[Node A]  →  output "goal"  →  [Node B]
          ←  input "result" ←
```

**我的解释：**

```
没有端口时，想知道节点之间怎么传数据，要么：
  a) 读 C++ 代码（不想读）
  b) 读文档（可能过时）

有端口时，端口声明就是文档，Groot2 也能看到：
  providedPorts() 里写了 InputPort / OutputPort
  → 谁读、谁写、读什么类型，一目了然
```

### 2.2 节点组合和子树作用域

**原文：**
> 直接用黑版时，**命名冲突**马上就会出现。
>
> 想想 `goal`、`result`、`target`、`value` 这种通用名字——两个不同厂商写的节点可能都用 `target`，但类型完全不同。

**看例子：**

```
厂商 A 写的 GraspObject： 读黑版 target（类型：3D Pose）
厂商 B 写的 MoveBase：    读黑版 target（类型：2D Pose）

如果两个节点在同一个树里 → target 冲突了！
```

**端口通过 remap 解决这个问题：**

```xml
<GraspObject target="{grasp_target}"/>    <!-- remap 到 grasp_target -->
<MoveBase    target="{nav_target}"/>      <!-- remap 到 nav_target -->
```

两个节点内部都写死了 `"target"`，但通过 XML 的 remap 映射到不同的黑版 key，完美解决。

**对于子树也是一样——Tutorial 06 讲过的 remap 就是为了解决子树间的命名冲突。**

## 三、总结：永远不要直接访问黑版

**原文列出了 5 个问题：**

```cpp
// ✅ 推荐：用端口
getInput("goal", goal);
setOutput("result", result);

// ❌ 强烈不推荐：直接访问黑版
config().blackboard->get("goal", goal);
config().blackboard->set("result", result);
```

**直接访问黑版的 5 个问题：**

| # | 问题 | 说明 |
|---|---|---|
| 1 | **名字硬编码** | `"goal"` `"result"` 写在 C++ 里，要改必须重新编译。端口在 XML 里 remap，改 XML 就行 |
| 2 | **不是自文档的** | 只有读 C++ 代码才能知道节点在读写什么黑版条目。端口声明 `providedPorts()` 就是文档 |
| 3 | **Factory 不知道数据流** | 端口方式下，`BehaviorTreeFactory` 可以检查端口连接是否错误。直接访问黑版则没有这个能力 |
| 4 | **SubTree 下可能出问题** | 子树有自己的黑版作用域，直接访问可能读到错误的副本 |
| 5 | **convertFromString 不工作** | 直接访问黑版时，类型转换字符串的功能不会自动触发 |

## 四、翻译成人话

**官方态度很明确：**

```
端口（Port）  = 黑版的"正规接口"
getInput/setOutput  = 正确的数据访问方式

黑版（Blackboard） = 实现细节，不要碰它
config().blackboard->get/set = 错误的做法
```

**类比：**

```
端口 → 函数参数（声明清晰、类型安全、调用方可重新命名）
黑版 → 全局变量（命名冲突、数据流不透明、难以调试）
```
