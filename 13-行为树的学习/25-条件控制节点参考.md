# Conditional Control Nodes 逐段解释

> 来源：https://behaviortree.dev/docs/nodes-library/ConditionalControlNodes
> 说明：这篇讲的是 BT.CPP 内置的两个**条件控制节点**——IfThenElse 和 WhileDoElse，它们都是"根据条件结果选择执行哪个分支"。

---

## 一、核心概念

**原文大意：**
> 这些控制节点根据**第一个子节点（条件）** 的结果，来决定执行哪个子节点。
>
> 内置了两种：
> - **IfThenElse**：条件只检查一次
> - **WhileDoElse**：条件每次 tick 都重新检查
>
> 两者必须恰好有 **2 或 3 个子节点**。

**固定结构：**

```
第 1 个子节点 = 条件（condition）
第 2 个子节点 = 条件为真时执行（then/do）
第 3 个子节点 = 条件为假时执行（else，可选）
```

---

## 二、IfThenElse（非响应式）

**原文：**
> IfThenElse 是一个**非响应式**的条件节点。
>
> - 条件**只评估一次**
> - 如果第 2 或第 3 个子节点返回 RUNNING，后续 tick 中条件**不会重新评估**

**XML 示例：**

```xml
<IfThenElse>
    <IsDoorOpen/>           <!-- 条件：门开了吗？只检查一次 -->
    <WalkThrough/>          <!-- 开了 → 穿过去 -->
    <TryAnotherPath/>       <!-- 没开 → 走另一条路（可选） -->
</IfThenElse>
```

**执行流程：**

```
tick 1: IfThenElse
  → Child 1（IsDoorOpen）→ SUCCESS ✅（门开了）
  → Child 2（WalkThrough）→ RUNNING 🔄（正在走）
  IfThenElse → RUNNING 🔄

tick 2: IfThenElse
  → （条件不重新检查，门关了也不知道）
  → Child 2（WalkThrough）→ 继续 → SUCCESS ✅
  IfThenElse → SUCCESS ✅
```

**只有 2 个子节点时：**

```xml
<IfThenElse>
    <IsDoorOpen/>           <!-- 条件 -->
    <WalkThrough/>          <!-- then -->
</IfThenElse>
<!-- 没有 else 分支，条件失败时等同于 AlwaysFailure，返回 FAILURE -->
```

---

## 三、WhileDoElse（响应式）

**原文：**
> WhileDoElse 是 IfThenElse 的**响应式**变体。条件**每次 tick 都重新评估**。
>
> 如果第 2 或第 3 个子节点正在 RUNNING，而条件结果发生了变化，**正在运行的子节点会被 halt**，然后切换到另一个分支。

**XML 示例：**

```xml
<WhileDoElse>
    <IsBatteryOK/>          <!-- 条件：电量OK吗？每次 tick 都检查 -->
    <ContinueMission/>      <!-- OK → 继续执行任务 -->
    <GoToChargingStation/>  <!-- 没电 → 去充电（可选） -->
</WhileDoElse>
```

**执行流程：**

```
tick 1: WhileDoElse
  → Child 1（IsBatteryOK）→ SUCCESS ✅（电量够）
  → Child 2（ContinueMission）→ RUNNING 🔄（正在做任务）
  WhileDoElse → RUNNING 🔄

tick 2: WhileDoElse
  → Child 1（IsBatteryOK）→ FAILURE ❌（电量掉了！）
  → 条件变了！→ halt Child 2（中断正在做的任务）
  → Child 3（GoToChargingStation）→ RUNNING 🔄（开始去充电）
  WhileDoElse → RUNNING 🔄

tick 3: WhileDoElse
  → Child 1（IsBatteryOK）→ FAILURE ❌（还在充电）
  → Child 3（GoToChargingStation）→ SUCCESS ✅（到了充电站）
  WhileDoElse → SUCCESS ✅
```

---

## 四、IfThenElse vs WhileDoElse 对比

| 特性 | IfThenElse | WhileDoElse |
|---|---|---|
| **条件重新评估** | ❌ 不重新评估 | ✅ 每次 tick 都重新评估 |
| **响应式** | ❌ 不是 | ✅ 是 |
| **条件变化时 halt 子节点** | — | ✅ 会自动 halt |
| **适用场景** | 一次性分支（如果...就...） | 持续监控（当...时...才...） |

**选型建议：**

```
条件判断一次就够了？
├── 是 → IfThenElse（比如"检查门是否开着，走哪条路"）
└── 需要持续监控？
    └── WhileDoElse（比如"电量够就干活，不够就充电"）
```

## 五、跟其他实现方式对比

**回顾 Tutorial 05（CrossDoor 示例）：**

```xml
<!-- 之前用 Fallback + Inverter 实现的 if-then-else -->
<Fallback>
    <Inverter>
        <IsDoorClosed/>
    </Inverter>
    <OpenDoor/>
</Fallback>
```

**也可以用 IfThenElse：**

```xml
<IfThenElse>
    <IsDoorOpen/>      <!-- 条件 -->
    <PassThrough/>     <!-- 开了 → 直接走 -->
    <OpenDoor/>        <!-- 没开 → 开门 -->
</IfThenElse>
```

**对比：**

```
Fallback + Inverter 方式：
  "如果门关着（inverter），就开门"
  逻辑绕了 Inverter 那一层

IfThenElse 方式：
  "如果门开着，就穿过去；否则，就开门"
  逻辑直接，看着像代码里的 if-else
```

**而 WhileDoElse 不能简单用 Sequence/Fallback 替代——因为 Sequence/Fallback 不具备"条件变化了就会 halt 正在运行的子节点"的能力。**

---

**一句话总结：**
> `IfThenElse` = "检查一次，决定走哪条路"；`WhileDoElse` = "每次 tick 都检查，条件变了马上切换"。两个都是 3 个子节点的 if-then-else 结构。
