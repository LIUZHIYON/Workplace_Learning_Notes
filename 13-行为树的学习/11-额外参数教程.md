# Tutorial 08: Pass additional arguments 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_08_additional_args
> 说明：前面所有节点的构造函数签名都是固定的 `(name, config)`。这篇教你**怎么给自定义节点传额外参数**——比如传一个 ROS2 节点句柄、配置文件路径等。

---

## 一、问题背景

**原文大意：**
> 之前每个自定义节点的构造函数都是：
> ```cpp
> MyNode(const std::string& name, const NodeConfig& config);
> ```
> 
> 但在某些场景下，我们希望传额外的参数——指针、引用、配置值等。
> 
> ⚠️ **不要在端口或黑版里传这些东西！** 那是不对的用法。

**我的解释：**

```
人的直觉（错误做法）：
  "那就把参数写成 InputPort 好了……"

官方说（别这么做）：
  如果满足以下条件，不要用端口/黑版：
  ① 参数在"部署时"（创建树时）就知道了
  ② 参数在运行期间不会变化
  ③ 参数不需要从 XML 设置
```

**什么时候用端口/黑版？**

| 场景 | 用端口？ | 用构造参数？ |
|---|---|---|
| 从 XML 读 `goal` 位置 | ✅ 端口 | ❌ |
| 运行时变化的电池阈值 | ✅ 端口 | ❌ |
| 固定的 ROS2 节点句柄 | ❌ **不要** | ✅ **用构造参数** |
| 固定的配置文件路径 | ❌ **不要** | ✅ **用构造参数** |
| 机器人型号标识符（固定） | ❌ **不要** | ✅ **用构造参数** |

## 二、方法 1：给构造函数加参数（推荐）

```cpp
class Action_A : public SyncActionNode
{
public:
  // 构造函数多了两个自定义参数
  Action_A(const std::string& name, const NodeConfig& config,
           int arg_int, std::string arg_str)
    : SyncActionNode(name, config),
      _arg1(arg_int),
      _arg2(arg_str) {}

  static PortsList providedPorts() { return {}; }

  NodeStatus tick() override {
    std::cout << "_arg1: " << _arg1
              << " _arg2: " << _arg2 << std::endl;
    return NodeStatus::SUCCESS;
  }

private:
  int _arg1;
  std::string _arg2;
};
```

**注册时传参数：**

```cpp
BT::BehaviorTreeFactory factory;

// 注册时直接传额外参数！
factory.registerNodeType<Action_A>("Action_A", 42, "hello world");

// 如果你喜欢显式写出模板参数类型：
// factory.registerNodeType<Action_A, int, std::string>("Action_A", 42, "hello world");
```

**我的解释：**

```
registerNodeType 的模板参数可以多于 1 个：
  第 1 个：你的节点类（必须有）
  第 2+ 个：构造函数的额外参数类型（可选）

registerNodeType 的调用参数：
  第 1 个：XML 标签名（"Action_A"）
  第 2+ 个：传给构造函数的额外参数（42, "hello world"）
```

**控制台输出：**

```
_arg1: 42 _arg2: hello world
```

## 三、方法 2：用 initialize 方法（不同的实例可以传不同的值）

如果你的节点在**同一棵树里有多个实例**，每个实例需要传**不同的值**，方法 1 就不太方便了（因为注册时参数是固定的）。这时候可以用 `initialize` + `applyVisitor`。

**节点定义：**

```cpp
class Action_B : public SyncActionNode
{
public:
  // 构造函数保持标准签名
  Action_B(const std::string& name, const NodeConfig& config)
    : SyncActionNode(name, config) {}

  // 额外加一个初始化方法
  void initialize(int arg_int, const std::string& arg_str)
  {
    _arg1 = arg_int;
    _arg2 = arg_str;
  }

  static PortsList providedPorts() { return {}; }

  NodeStatus tick() override {
    std::cout << "_arg1: " << _arg1
              << " _arg2: " << _arg2 << std::endl;
    return NodeStatus::SUCCESS;
  }

private:
  int _arg1;
  std::string _arg2;
};
```

**注册和初始化：**

```cpp
BT::BehaviorTreeFactory factory;

// 标准注册，不传额外参数
factory.registerNodeType<Action_B>("Action_B");

auto tree = factory.createTreeFromText(xml_text);

// 用 visitor 遍历所有节点，找到 Action_B 的实例逐个初始化
auto visitor = [](TreeNode* node)
{
  if (auto action_B_node = dynamic_cast<Action_B*>(node))
  {
    // 不同的实例可以传不同的值！
    action_B_node->initialize(69, "interesting_value");
  }
};

// 对整个树的节点应用 visitor
tree.applyVisitor(visitor);
```

**我的解释：**

```
方法 1（构造参数）：                       方法 2（initialize + visitor）：
同一个类型的所有实例共享同一组参数          每个实例可以有不同的参数

factory.registerNodeType<A>("A", 42, "x")   factory.registerNodeType<B>("B")
                                    ↓
  <Action_A/>  → 全部拿到 (42, "x")          <Action_B/>  → 通过 visitor 单独设置
  <Action_A/>  → 全部拿到 (42, "x")          <Action_B/>  → 可以传不同的值
```

## 四、两种方法对比

| 维度 | 方法 1：构造参数 | 方法 2：initialize + visitor |
|---|---|---|
| 使用场景 | 同一个节点类型所有实例参数相同 | 同一个节点类型参数因实例而异 |
| 代码量 | 少 | 多一些 |
| 类型安全 | ✅ 编译时保证 | ✅ 编译时保证 |
| 灵活性 | ❌ 注册时就固定了 | ✅ 创建树后还能改 |
| 推荐度 | **推荐**（原文说 recommended） | 特殊场景用 |

## 五、实际项目中最常见的用法

给节点传一个 ROS2 节点句柄：

```cpp
class MoveToPose : public BT::SyncActionNode
{
public:
  MoveToPose(const std::string& name, const NodeConfig& config,
             rclcpp::Node::SharedPtr ros_node)
    : SyncActionNode(name, config),
      ros_node_(ros_node) {}

  NodeStatus tick() override {
    // 直接用 ros_node_ 创建 publisher/subscriber
    auto pub = ros_node_->create_publisher<geometry_msgs::msg::Twist>("/cmd_vel", 10);
    // ...
    return SUCCESS;
  }

private:
  rclcpp::Node::SharedPtr ros_node_;
};

// 注册
auto ros_node = std::make_shared<rclcpp::Node>("bt_node");
factory.registerNodeType<MoveToPose>("MoveToPose", ros_node);
```

**之前错误做法**（有人会这样写，但官方说不推荐）：

```cpp
// ❌ 把 ROS 句柄放到黑版里传，不好！
// 理由：它不会在运行时变化，而且不从 XML 设置。
<MoveToPose ros_node="{ros_node}"/>
```

## 跟之前教程的关系

```
教程 02/03：通过端口/黑版传数据（运行时变化的数据）
教程 08：   通过构造参数传数据（部署时固定的数据）
              ↑ 这是两个完全不同的使用场景
```

**一句话总结：**
> 端口传的是**运行时变化**的数据（位置、速度、状态）；构造参数传的是**部署时固定**的数据（ROS2 句柄、配置路径、参数）。不要把固定参数塞进黑版。
