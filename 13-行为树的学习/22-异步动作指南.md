# Asynchronous Actions Guide 逐段解释

> 来源：https://behaviortree.dev/docs/guides/asynchronous_nodes
> 说明：这篇深入讲解了 BT.CPP 的**并发模型**——树是单线程的，但节点可以"假装异步"通过返回 RUNNING 实现响应式行为。以及为什么**不要用 `ThreadedAction`**。

---

## 一、Concurrency vs Parallelism（并发 vs 并行）

**原文的定义：**

| 概念 | 定义 |
|---|---|
| **Concurrency（并发）** | 多个任务**可以在重叠的时间段内**开始、运行和完成。不一定是同时运行。 |
| **Parallelism（并行）** | 多个任务**在不同线程上同时运行**。 |

**BT.CPP 的选择：**

> - 树的执行引擎是**单线程**的
> - 所有 `tick()` 方法**顺序执行**
> - 如果任何一个 `tick()` 阻塞，**整棵树都会被卡住**
> - 我们通过**并发**和**异步执行**来实现响应式行为

**我的解释：**

```
坏消息：BT.CPP 不是多线程的，不能同时 tick 两个节点。
好消息：你也不需要多线程。通过"快速返回 RUNNING + 轮询"就能实现响应式。
```

---

## 二、Asynchronous vs Synchronous（异步 vs 同步）

**异步节点的两个要求：**

1. **可以返回 `RUNNING`** 而不是 `SUCCESS` 或 `FAILURE`
2. **调用 `halt()` 时必须能快速停止**

**典型模式（StatefulActionNode）：**

```
tick 1: onStart() → 发出请求 → 返回 RUNNING
tick 2: onRunning() → 检查回复 → 还没到 → 返回 RUNNING
tick 3: onRunning() → 检查回复 → 到了 → 返回 SUCCESS

中途如果被 halt：
  onHalted() → 清理资源 → 结束
```

**整个树在异步节点返回 RUNNING 时的状态：**

```
Sequence → RUNNING 🔄
├── BatteryOK → SUCCESS ✅（之前检查过了）
├── MoveBase → RUNNING 🔄（异步，还在进行中）
└── SaySomething → IDLE（还没轮到）
```

RUNNING 沿树往上传播，整棵树也处于 RUNNING 状态。

## 三、`StatefulActionNode` 的正确实现

**`SleepNode` 的正确异步版：**

```cpp
class SleepNode : public BT::StatefulActionNode
{
public:
  SleepNode(const std::string& name, const NodeConfig& config)
    : BT::StatefulActionNode(name, config) {}

  static PortsList providedPorts() {
    return { BT::InputPort<int>("msec") };
  }

  NodeStatus onStart() override {
    int msec = 0;
    getInput("msec", msec);
    if (msec <= 0) {
      return NodeStatus::SUCCESS;  // 不用等，直接成功
    }
    deadline_ = system_clock::now() + milliseconds(msec);
    return NodeStatus::RUNNING;    // 需要等，进入 RUNNING
  }

  NodeStatus onRunning() override {
    if (system_clock::now() >= deadline_) {
      return NodeStatus::SUCCESS;
    }
    return NodeStatus::RUNNING;    // 还没到时间
  }

  void onHalted() override {
    // 如果被中断，可以在这里清理
    std::cout << "SleepNode interrupted" << std::endl;
  }

private:
  system_clock::time_point deadline_;
};
```

**执行流程：**
```
tick 1：onStart() → 记录截止时间 → RUNNING 🔄
tick 2：onRunning() → 还没到 → RUNNING 🔄
...
tick N：onRunning() → 时间到了 → SUCCESS ✅
如果在等待中被 halt → onHalted() 被调用
```

**关键点：** 每次 `tick()` 都不能阻塞，**检查一下状态就立刻返回**。

## 四、错误示范——不要阻塞树的执行

**错误写法（用 blocking sleep）：**

```cpp
class BadSleepNode : public BT::ActionNodeBase {
  NodeStatus tick() override {
    int msec = 0;
    getInput("msec", msec);
    // ❌ 这行会卡死整棵树！
    std::this_thread::sleep_for(milliseconds(msec));
    return NodeStatus::SUCCESS;
  }
  void halt() override {
    // ❌ 根本没机会调用 halt()，因为树被卡死了
    // 就算调用了，也 interrupt 不了 sleep_for()
  }
};
```

**也错误（用 `ThreadedAction`，但没处理 halt）：**

```cpp
class BadSleepNode : public BT::ThreadedAction {
  NodeStatus tick() override {
    int msec = 0;
    getInput("msec", msec);
    // 虽然在另一个线程跑，不卡树
    // 但 halt() 无法中断这个 sleep_for()
    std::this_thread::sleep_for(milliseconds(msec));
    return NodeStatus::SUCCESS;
  }
  // ❌ halt() 不能终止线程里的 sleep_for()
};
```

**正确的做法——用 condition_variable 实现可中断的等待：**

```cpp
class InterruptableSleepNode : public BT::ThreadedAction {
  NodeStatus tick() override {
    // ...
    std::unique_lock<std::mutex> lk(mutex_);
    // 用 condition_variable 等待，而不是 sleep_for
    cv_.wait_for(lk, milliseconds(msec));
    // 这样 halt() 可以通过 notify 提前唤醒
  }

  void halt() override {
    // 通知 condition_variable 提前醒来
    cv_.notify_one();
  }
};
```

但**官方还是推荐用 `StatefulActionNode`**，因为它不需要处理线程安全的问题。

## 五、并发和线程安全的建议

**BT.CPP 不推荐自己开线程的原因：**

| 问题 | 说明 |
|---|---|
| 黑版线程安全 | 多线程同时访问黑版需要加锁（`getLockedPortContent`） |
| 实际不需要 | 大多数时候返回 RUNNING + 轮询就够了 |
| halt 难以实现 | 开线程容易，**安全地停止线程**难 |

**如果必须用线程（比如调用阻塞式硬件库）：**

```cpp
// 用 ThreadedAction + condition_variable 实现可中断
class MyAction : public BT::ThreadedAction {
  // 在 tick() 里用 cv_.wait_for() 替代 sleep
  // 在 halt() 里调用 cv_.notify_one() / notify_all()
};
```

## 六、正确实现异步 Action 的流程总结

```
Step 1: 继承 StatefulActionNode（不是 SyncActionNode、不是 ThreadedAction）
Step 2: 实现 onStart() → 记录开始，返回 RUNNING
Step 3: 实现 onRunning() → 检查是否完成，返回 SUCCESS 或 RUNNING
Step 4: 实现 onHalted() → 清理资源
Step 5: onStart/onRunning 里不要做阻塞操作
```

**用 StatefulActionNode vs 用 ThreadedAction：**

| 维度 | StatefulActionNode ✅ | ThreadedAction |
|---|---|---|
| 线程模型 | 主线程轮询（无并发问题） | 开新线程 |
| 实现难度 | 简单 | 中等（需要处理同步） |
| halt 支持 | 自动 | 需要手动实现 condition_variable |
| 黑版访问 | 直接 getInput/setOutput | 需要锁保护 |
| 推荐度 | **推荐** | 仅当调用阻塞式第三方库时使用 |

---

**一句话总结：**
> BT.CPP 是单线程引擎，异步通过"快速返回 RUNNING + 轮询"实现。`StatefulActionNode` 是实现异步节点的推荐方式，`ThreadedAction` 不推荐因为线程安全难处理、halt 难实现。
