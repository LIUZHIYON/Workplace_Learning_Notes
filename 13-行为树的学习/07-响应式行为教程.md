# Tutorial 04: Reactive behaviors 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_04_sequence
> 说明：这篇讲的是**异步 Action**（返回 RUNNING 的那种）跟 **ReactiveSequence** 一起用的时候，Sequence 和 ReactiveSequence 的行为差异。

---

## 一、引入

**原文大意：**
> 这篇教程演示 `SequenceNode` 和 `ReactiveSequence` 的区别。
> 
> 我们会实现一个**异步 Action**——需要花很长时间才能完成的动作，在完成之前一直返回 `RUNNING`。
> 
> 异步 Action 的要求：
> 1. `tick()` 里不能阻塞太久，要尽快返回
> 2. 如果 `halt()` 被调用，要能尽快中止

---

## 二、StatefulActionNode（有状态的 Action 节点）

**原文：**
> `StatefulActionNode` 是实现异步 Action 的首选方式。特别适合 **request-reply（请求-回复）** 模式——发一个异步请求，然后定期检查回复有没有到。

**需要重写三个方法，而不是一个 `tick()`：**

| 方法 | 什么时候调用 | 返回值 |
|---|---|---|
| `onStart()` | 节点第一次被 tick（从 IDLE 状态变成 RUNNING） | SUCCESS / FAILURE / RUNNING |
| `onRunning()` | 节点处于 RUNNING 状态时，每次 tick 都调这个 | SUCCESS / FAILURE / RUNNING |
| `onHalted()` | 这个节点被其他节点中止时 | void（没有返回值） |

**生命周期：**

```
状态机：
  IDLE → onStart() → RUNNING → onRunning() → onRunning() → ... → SUCCESS/FAILURE
                              ↓
                           onHalted()（被外部打断）
```

**示例：模拟一个导航动作 `MoveBaseAction`**

```cpp
// 用来模拟目标位置
struct Pose2D {
    double x, y, theta;
};

class MoveBaseAction : public BT::StatefulActionNode
{
public:
  MoveBaseAction(const std::string& name, const BT::NodeConfig& config)
    : StatefulActionNode(name, config)
  {}

  static BT::PortsList providedPorts()
  {
    return{ BT::InputPort<Pose2D>("goal") };
  }

  // 第一次被调用时触发
  BT::NodeStatus onStart() override
  {
    if (!getInput<Pose2D>("goal", _goal))
    {
      throw RuntimeError("missing required input [goal]");
    }
    printf("[ MoveBase: SEND REQUEST ]. goal: x=%f y=%f theta=%f\n",
           _goal.x, _goal.y, _goal.theta);

    // 模拟 220ms 后完成
    _completion_time = system_clock::now() + milliseconds(220);

    return BT::NodeStatus::RUNNING;  // ← 返回 RUNNING，表示还没完成
  }

  // 之后每个 tick 都调这个，直到返回 SUCCESS 或 FAILURE
  BT::NodeStatus onRunning() override
  {
    // 模拟每次 tick 检查回复
    sleep_for(milliseconds(10));

    if (system_clock::now() >= _completion_time)
    {
      std::cout << "[ MoveBase: FINISHED ]" << std::endl;
      return BT::NodeStatus::SUCCESS;
    }
    return BT::NodeStatus::RUNNING;  // 还没完成，继续
  }

  // 被中止时调用
  void onHalted() override
  {
    printf("[ MoveBase: ABORTED ]");
  }

private:
  Pose2D _goal;
  system_clock::time_point _completion_time;
};
```

**我的解释：**

```
tick 1：Sequence → BatteryOK → SUCCESS
                   SaySomething → SUCCESS
                   MoveBaseAction.onStart() → "SEND REQUEST" → RUNNING 🔄

tick 2：Sequence → BatteryOK → SUCCESS（重新检查）
                   SaySomething → SUCCESS（又打印一次！）
                   MoveBaseAction.onRunning() → 还没到时间 → RUNNING 🔄

tick 3：Sequence → BatteryOK → SUCCESS
                   SaySomething → SUCCESS（又又打印！）
                   MoveBaseAction.onRunning() → 还没到 → RUNNING 🔄

...

tick n：Sequence → BatteryOK → SUCCESS
                   SaySomething → SUCCESS
                   MoveBaseAction.onRunning() → 时间到了 → SUCCESS ✅
                   SaySomething("mission completed!") → SUCCESS ✅
         → Sequence 返回 SUCCESS ✅
```

**等等，这有问题！** `SaySomething("mission started...")` 每次 tick 都执行了！而且 BatteryOK 每次都重新检查了！

这就是 **Sequence** 的问题——

## 三、Sequence VS ReactiveSequence

**原文用一个例子来对比：**

```xml
<root BTCPP_format="4">
    <BehaviorTree>
       <Sequence>
           <BatteryOK/>
           <SaySomething   message="mission started..."/>
           <MoveBase       goal="1;2;3"/>
           <SaySomething   message="mission completed!"/>
       </Sequence>
    </BehaviorTree>
</root>
```

**主循环的代码（手动 loop，不是 `tickWhileRunning`）：**

```cpp
int main()
{
  BT::BehaviorTreeFactory factory;
  factory.registerSimpleCondition("BatteryOK", std::bind(CheckBattery));
  factory.registerNodeType<MoveBaseAction>("MoveBase");
  factory.registerNodeType<SaySomething>("SaySomething");

  auto tree = factory.createTreeFromText(xml_text);

  std::cout << "--- ticking\n";
  auto status = tree.tickOnce();
  std::cout << "--- status: " << toStr(status) << "\n\n";

  while (status == NodeStatus::RUNNING)
  {
    tree.sleep(chrono::milliseconds(100));

    std::cout << "--- ticking\n";
    status = tree.tickOnce();
    std::cout << "--- status: " << toStr(status) << "\n\n";
  }

  return 0;
}
```

**用 Sequence 的输出：**

```
--- ticking
[Battery: OK]
Robot says: mission started...
[ MoveBase: SEND REQUEST ]. goal: ...    ← 发出请求，返回 RUNNING
--- status: RUNNING

--- ticking
[Battery: OK]                            ← 又检查了一次
Robot says: mission started...           ← 又打印了 "mission started..."！
[ MoveBase: FINISHED ]                   ← 移动完成
--- status: RUNNING

--- ticking
[Battery: OK]                            ← 又检查
Robot says: mission started...           ← 又打印 "mission started..."
[ MoveBase: FINISHED ]                   ← 已经完成了，返回 SUCCESS
Robot says: mission completed!           ← 终于到这一步了！
--- status: SUCCESS
```

**问题：** `BatteryOK` 每次 tick 都检查、`SaySomething("mission started...")` 每次 tick 都打印——但它们应该**只执行一次**！

**用 `ReactiveSequence` 替换 `Sequence`：**

```xml
<ReactiveSequence>
    <BatteryOK/>
    <SaySomething   message="mission started..."/>
    <MoveBase       goal="1;2;3"/>
    <SaySomething   message="mission completed!"/>
</ReactiveSequence>
```

**用 ReactiveSequence 的输出：**

```
--- ticking
[Battery: OK]
Robot says: mission started...
[ MoveBase: SEND REQUEST ]. goal: ...    ← 发出请求，返回 RUNNING
--- status: RUNNING

--- ticking
[Battery: OK]                            ← 只重新检查 BatteryOK（条件需要实时监测）
--- status: RUNNING                       ← 但不重新执行 SaySomething 和 MoveBase

--- ticking
[Battery: OK]
--- status: RUNNING

--- ticking
[Battery: OK]
[ MoveBase: FINISHED ]                   ← 移动完成
Robot says: mission completed!
--- status: SUCCESS
```

## 四、ReactiveSequence 的规则

**原文给出了 ReactiveSequence 的行为规则：**

> **ReactiveSequence** 每次 tick 时，会**重新执行所有已经返回 SUCCESS 的子节点**。但如果某个子节点返回 RUNNING，它**不会**重新执行它前面的子节点（除了第一个节点！）。

**具体来说：**

```
            ReactiveSequence
      ├── BatteryOK         → 每次 tick 都重新执行（条件节点，需要实时检查）
      ├── SaySomething      → 只执行一次（因为 MoveBase 还在 RUNNING，不会回头重跑）
      ├── MoveBase          → RUNNING 状态被保留，继续 onRunning
      └── SaySomething      → 等 MoveBase 完成后才执行
```

**第一个子节点是特殊的——** 原文说 "the first child is always restarted"——第一个节点（通常是条件检查）每次 tick 都会重新执行。这是为了保证安全（比如每次都要确认电量是否还够）。

## 五、什么时候用 Sequence，什么时候用 ReactiveSequence

| 场景 | 用哪个 | 原因 |
|---|---|---|
| 所有节点都是同步（瞬间返回） | **Sequence** | 没有 RUNNING 状态的节点，没区别 |
| 有异步 Action 且**不需要**实时重新检查条件 | **Sequence** | 简单，不会漏执行 |
| **有异步 Action 且需要实时重新检查条件**（比如电池） | **ReactiveSequence** | 条件节点每次 tick 都检查，安全 |
| 条件频繁变化，需要立即响应 | **ReactiveSequence** | 比如"有人靠近就停止"，要实时性 |

**选型决策：**

```
你的 Action 返回 RUNNING 吗？
├── 不返回（同步） → 用 Sequence 就行，没区别
└── 返回（异步）
    ├── 前面的条件/动作不需要重新执行 → 用 Sequence（但要注意重复执行的问题）
    └── 前面的条件需要实时监测 → ReactiveSequence
```

## 六、Sequence 和 ReactiveSequence 的行为对比

```
Sequence 行为：
  tick 1: A → SUCCESS, B → RUNNING 🔄
  tick 2: A → SUCCESS, B → RUNNING 🔄    ← A 重新执行了一遍！
  tick 3: A → SUCCESS, B → RUNNING 🔄    ← A 又执行了一遍...
  问题：B 前面的节点每次 tick 都重复执行

ReactiveSequence 行为：
  tick 1: A → SUCCESS, B → RUNNING 🔄
  tick 2: A → SUCCESS                      ← 第一个节点 A 重新执行
           (跳过 B 前面的其他 SUCCESS 节点)
           B → 继续 onRunning() 🔄
  tick 3: A → SUCCESS                      ← 第一个节点 A 重新执行
           B → 继续 onRunning() 🔄
  ...
  tick n: A → SUCCESS
           B → SUCCESS ✅ → C → ...
```

**关键区别：**

| 行为 | Sequence | ReactiveSequence |
|---|---|---|
| 子节点返回 RUNNING | 整个 **Sequence** 返回 RUNNING | 整个 **ReactiveSequence** 返回 RUNNING |
| 下次 tick 从哪开始 | **从头开始**（第一个子节点重新执行） | **第一个子节点重新执行**，然后从上次 RUNNING 的节点继续 |
| 中间的 SUCCESS 节点 | 每次重新执行 | 不重新执行（除非它们前面有节点变成 FAILURE） |
| 适用场景 | 全是同步节点，或不需要实时性 | 有异步 Action，且条件需要实时监测 |
