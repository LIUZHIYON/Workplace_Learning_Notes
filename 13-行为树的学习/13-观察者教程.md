# Tutorial 10: Loggers and Observer 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_10_observer
> 说明：这篇介绍 BT.CPP 的**日志/观察者机制**——让你知道树运行时每个节点经历了什么状态变化，特别适合**单元测试**。

---

## 一、什么是 Logger

**原文大意：**
> BT.CPP 提供了运行时向树附加 **logger** 的机制。Logger 是一个类，在每次 TreeNode 状态变化时触发回调——这是典型的**观察者模式**，并且是非侵入式的。

**回调函数的签名：**

```cpp
virtual void callback(
    BT::Duration timestamp,      // 状态变化发生的时间
    const TreeNode& node,        // 状态变化的节点
    NodeStatus prev_status,      // 之前的状态
    NodeStatus status            // 新的状态
);
```

**我的解释：**

```
每次任何节点发生 IDLE→RUNNING→SUCCESS/FAILURE 这样的状态变化时，
logger 的 callback 就会被触发，你可以在这里记录日志、截图、发消息等。
```

---

## 二、TreeObserver 类——最有用的 logger

**原文大意：**
> 做**单元测试**时，经常需要统计某个节点执行了多少次 SUCCESS 或 FAILURE。`TreeObserver` 就是为此设计的。

**每个节点会被统计以下几项：**

```cpp
struct NodeStatistics {
    NodeStatus last_result;         // 最近一次 SUCCESS 或 FAILURE
    NodeStatus current_status;      // 当前状态（包括 IDLE / SKIPPED）
    unsigned transitions_count;     // 状态变化次数（排除 IDLE）
    unsigned success_count;         // SUCCESS 次数
    unsigned failure_count;         // FAILURE 次数
    unsigned skip_count;            // SKIPPED 次数
    Duration last_timestamp;        // 最近一次状态变化的时间戳
};
```

**我的解释：**

| 统计项 | 含义 |
|---|---|
| `transitions_count` | 这个节点总共被 tick 了多少次 |
| `success_count` | 返回 SUCCESS 的次数 |
| `failure_count` | 返回 FAILURE 的次数 |
| `skip_count` | 被跳过的次数（比如 Fallback 后面的节点） |

## 三、节点唯一标识：UID 和 fullPath

**原文大意：**
> Observer 需要能唯一标识每个节点。有两种方式：

| 方式 | 说明 | 示例 |
|---|---|---|
| **UID** | 按深度优先遍历顺序分配的整数 | `1`, `2`, `3`... |
| **fullPath** | 人类可读的路径字符串 | `mysub/sub_nested/action_subB` |

**完整路径的规则：**
```
子树名/嵌套子树名/节点名
```

如果节点没有设置 `name` 属性，自动使用 `类型名::UID` 格式。

---

## 四、XML 示例

```xml
<root BTCPP_format="4">
  <BehaviorTree ID="MainTree">
    <Sequence>
      <Fallback>
        <AlwaysFailure name="failing_action"/>
        <SubTree ID="SubTreeA" name="mysub"/>
      </Fallback>
      <AlwaysSuccess name="last_action"/>
    </Sequence>
  </BehaviorTree>

  <BehaviorTree ID="SubTreeA">
    <Sequence>
      <AlwaysSuccess name="action_subA"/>
      <SubTree ID="SubTreeB" name="sub_nested"/>
      <SubTree ID="SubTreeB"/>
    </Sequence>
  </BehaviorTree>

  <BehaviorTree ID="SubTreeB">
    <AlwaysSuccess name="action_subB"/>
  </BehaviorTree>
</root>
```

**对应的 UID → fullPath 映射：**

```
UID → fullPath
1  → Sequence::1                     ← 没有 name，自动生成
2  → Fallback::2                     ← 没有 name
3  → failing_action                  ← 有 name="failing_action"
4  → mysub                           ← SubTree 有 name="mysub"
5  → mysub/Sequence::5               ← 子树内的 Sequence，无 name
6  → mysub/action_subA               ← 子树内的 action
7  → mysub/sub_nested                ← 嵌套的 SubTree
8  → mysub/sub_nested/action_subB    ← 最深的 action
9  → mysub/SubTreeB::9               ← 第二个 SubTreeB，未命名
10 → mysub/SubTreeB::9/action_subB   ← 它的子节点
11 → last_action                     ← MainTree 最后一个 action
```

**关键点：**
- 同一个 SubTree 被引用两次（`sub_nested` 和未命名的 `SubTreeB`）→ 不同路径
- 路径是**唯一的**
- 没有写 `name` 属性的节点，路径会带 `类型名::UID`

## 五、C++ 用法——单元测试场景

```cpp
int main()
{
  BT::BehaviorTreeFactory factory;
  factory.registerBehaviorTreeFromText(xml_text);
  auto tree = factory.createTree("MainTree");

  // 1. 打印树结构（调试用）
  BT::printTreeRecursively(tree.rootNode());

  // 2. 创建 Observer，绑定到树
  BT::TreeObserver observer(tree);

  // 3. 打印 UID ↔ fullPath 映射
  std::map<uint16_t, std::string> ordered_UID_to_path;
  for (const auto& [name, uid] : observer.pathToUID()) {
    ordered_UID_to_path[uid] = name;
  }
  for (const auto& [uid, name] : ordered_UID_to_path) {
    std::cout << uid << " -> " << name << std::endl;
  }

  // 4. 执行树
  tree.tickWhileRunning();

  // 5. 获取特定节点的统计信息（用 fullPath 或 UID）
  const auto& last_action_stats = observer.getStatistics("last_action");
  assert(last_action_stats.transitions_count > 0);

  // 6. 打印所有节点的统计信息
  for (const auto& [uid, name] : ordered_UID_to_path) {
    const auto& stats = observer.getStatistics(uid);
    std::cout << "[" << name << "] \tT/S/F:  "
              << stats.transitions_count << "/"
              << stats.success_count << "/"
              << stats.failure_count << std::endl;
  }

  return 0;
}
```

**用 Observer 做单元测试的典型流程：**

```cpp
// 执行树运行
tree.tickWhileRunning();

// 断言：failing_action 一定失败了
const auto& fail_stats = observer.getStatistics("failing_action");
assert(fail_stats.failure_count == 1);
assert(fail_stats.success_count == 0);

// 断言：last_action 一定成功了
const auto& last_stats = observer.getStatistics("last_action");
assert(last_stats.success_count == 1);

// 断言：SubTreeB 第一次被跳过了（没有被执行）
const auto& subB_stats = observer.getStatistics("mysub/sub_nested/action_subB");
assert(subB_stats.transitions_count > 0);  // tick 过
```

## 六、主要用途

| 用途 | 说明 |
|---|---|
| **单元测试** | 检查特定节点是否按预期成功/失败 |
| **行为验证** | 验证 Fallback 的备选分支是否真的被跳过了 |
| **性能分析** | 统计每个节点的执行次数和耗时 |
| **调试** | 运行时观察节点的状态变化 |

**一句话总结：**
> `TreeObserver` 就像给行为树装了一个"黑匣子"，记录每个节点的 SUCCESS/FAILURE 次数。在**单元测试**里，你可以断言某个节点应该成功多少次、失败多少次，从而验证行为树逻辑是否正确。
