# Pre and Post conditions Guide 逐段解释

> 来源：https://behaviortree.dev/docs/guides/pre_post_conditions
> 说明：这篇是**前置条件和后置条件**的完整指南。结合脚本语言，可以在节点的 tick 之前/之后执行条件判断和赋值，**不需要写 C++ 代码**。

---

## 一、引入

**原文大意：**
> BT.CPP 4.x 引入了 Pre/Post Condition 机制——在所有节点上都支持的脚本化前置/后置处理，不需要修改 C++ 代码。

> ⚠️ **警告：** 脚本的目标不是写复杂代码，而是提高可读性、减少简单场景下的自定义 C++ 节点。脚本太长就该考虑用 C++ 实现了。

---

## 二、Pre conditions（前置条件）

**4 种前置条件：**

| 名称 | 作用 | 何时评估 |
|---|---|---|
| **`_skipIf`** | 条件为 true 时跳过这个节点 | 仅 IDLE 状态（一次） |
| **`_failureIf`** | 条件为 true 时跳过并返回 FAILURE | 仅 IDLE 状态（一次） |
| **`_successIf`** | 条件为 true 时跳过并返回 SUCCESS | 仅 IDLE 状态（一次） |
| **`_while`** | 如果 IDLE 时条件为 false 就跳过；如果 RUNNING 时条件变 false 就 halt 并返回 SKIPPED | IDLE 和 RUNNING（**每次 tick**） |

**重要：评估时间**

> ⚠️ **`_skipIf`、`_failureIf`、`_successIf` 只在节点从 IDLE 切换到其他状态时评估一次**，节点 RUNNING 期间**不会重新检查**。
>
> **只有 `_while`** 每次 tick 都检查，包括节点在 RUNNING 期间。
>
> 如果需要每次 tick 都检查条件，用 `<Precondition>` 装饰器节点 + `else="RUNNING"`。

**评估顺序：**

```
_failureIf → _successIf → _skipIf → _while
（第一个满足的条件决定结果）
```

## 三、示例：简化 Fallback + Inverter

**之前的写法**（Fallback + Inverter + ConditionNode）：

```xml
<Fallback>
    <Inverter>
        <IsDoorClosed/>
    </Inverter>
    <OpenDoor/>
</Fallback>
```

**用 `_skipIf` 的简洁写法：**

```xml
<OpenDoor _skipIf="!door_closed"/>
```

**翻译：** 如果 `door_closed` 为 false（门没关）→ 跳过 OpenDoor → Fallback 继续。  
**不再需要** `Inverter` + `IsDoorClosed` ConditionNode + `Fallback`，一行搞定。

## 四、`<Precondition>` vs inline 属性——何时每次 tick 重新检查

**inline 属性（`_skipIf` / `_successIf` 等）只在 IDLE 时检查一次：**

```xml
<!-- 只在 MoveToGoal 启动时检查，运行中变了不管 -->
<MoveToGoal _successIf="battery_ok"/>
```

**`<Precondition>` 装饰节点每次 tick 都检查：**

```xml
<!-- 每次 tick 都检查，如果电池掉了立刻知道 -->
<Precondition if="battery_ok" else="RUNNING">
    <MoveToGoal/>
</Precondition>
```

**区别：**

| 方式 | 检查时机 | 适用场景 |
|---|---|---|
| `_successIf="battery_ok"` | IDLE → RUNNING 时**一次** | 启动前检查一次就够了 |
| `<Precondition if="battery_ok" else="RUNNING">` | **每次 tick** | 需要实时监控条件 |

**为什么 `else="RUNNING"`？** 如果条件不满足时返回 `FAILURE`，父节点可能直接放弃整个分支。返回 `RUNNING` 表示"还没准备好，再等等"。

## 五、Post conditions（后置条件）

**4 种后置条件：**

| 名称 | 作用 |
|---|---|
| **`_onSuccess`** | 节点返回 SUCCESS 时执行这段脚本 |
| **`_onFailure`** | 节点返回 FAILURE 时执行这段脚本 |
| **`_post`** | 节点返回 SUCCESS 或 FAILURE 时都执行这段脚本 |
| **`_onHalted`** | 节点在 RUNNING 状态被 halt 时执行这段脚本 |

**示例——之前 vs 之后：**

**之前**（Sequence + Fallback + ForceFailure + SetBlackboard）：

```xml
<Fallback>
    <Sequence>
        <MoveBase goal="{target}"/>
        <SetBlackboard output_key="result" value="0"/>
    </Sequence>
    <ForceFailure>
        <SetBlackboard output_key="result" value="-1"/>
    </ForceFailure>
</Fallback>
```

**之后**（用 `_onSuccess` / `_onFailure`）：

```xml
<MoveBase goal="{target}"
          _onSuccess="result:=OK"
          _onFailure="result:=ERROR"/>
```

**去掉了多少节点？** 5 个 → 1 个节点，还支持枚举值。

## 六、设计模式：错误码

**原文给出了一个"错误码"设计模式：**

```
MoveBase 返回 error_code
├── error_code == 0？ → 成功
├── error_code == 1？ → 用 RecoveryOne
└── error_code == 2？ → 用 RecoveryTwo
```

**用 `_skipIf` 实现：**

```xml
<Sequence>
    <MoveBase goal="{target}" return="{error_code}"/>
    <RecoveryOne _skipIf="error_code!=1"/>
    <RecoveryTwo _skipIf="error_code!=2"/>
</Sequence>
```

**执行逻辑：**

```
Step 1: MoveBase 执行 → 输出 error_code
Step 2: RecoveryOne → 如果 error_code!=1 就跳过
Step 3: RecoveryTwo → 如果 error_code!=2 就跳过
```

## 七、设计模式：状态和声明式树

**原文给了另一个模式：**

```xml
<LeafNode _onSuccess="state:=IDLE"
          _onHalted="state:=BUSY"
          _onFailure="state:=ERROR"/>
```

节点成功 → 状态设为 IDLE；被中断 → 状态设为 BUSY；失败 → 状态设为 ERROR。

这样可以在树的更高层根据 `state` 的值做决策：

```xml
<SubTree ID="RecoverySequence" _skipIf="state != ERROR"/>
<SubTree ID="DoWork"           _skipIf="state != IDLE"/>
```

根据机器人当前状态，决定走哪条分支。

---

## 八、总结——什么时候用什么

| 场景 | 用什么 |
|---|---|
| 只需要启动前检查一次条件 | `_skipIf` / `_successIf` / `_failureIf` |
| 需要每次 tick 都检查 | `<Precondition>` 装饰节点 |
| 需要节点正在 RUNNING 时也监控条件 | `_while` |
| 节点成功时写黑版 | `_onSuccess` |
| 节点失败时写黑版 | `_onFailure` |
| 不管成功失败都要写 | `_post` |
| 节点被中断时写 | `_onHalted` |

**一句话总结：**
> Pre/Post conditions 让你在 XML 属性里直接写条件和赋值，替换掉原来需要额外 ConditionNode / Fallback / Sequence / SetBlackboard 才能实现的功能，简洁非常多。
