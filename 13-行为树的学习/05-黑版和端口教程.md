# Tutorial 02: Blackboard and ports 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_02_basic_ports
> 说明：这篇教程教你节点之间怎么传数据——输入端口、输出端口、黑版。

---

## 一、引入

**原文大意：**
> 自定义的 TreeNode 跟函数很像。函数可以有参数（输入）和返回值（输出），TreeNode 也一样。一个节点的输出可以成为另一个节点的输入。
> 
> BehaviorTree.CPP 通过**端口（Ports）**和**黑版（Blackboard）**来实现数据流，既灵活又是类型安全的。

**我的解释：**

教程 01 的节点都是"自娱自乐"——打印一句话就完了，不需要跟别的节点交换数据。

但实际场景里：
- `DetectObject` 检测到了物体 → 要把物体名字告诉 `GraspObject`
- `CheckBattery` 查到了电量 → 要告诉 `Charge` 节点需不需要充电

这时候就需要**端口 + 黑版**。

---

## 二、黑版的概念

原文的一个提示框总结了：

> - **黑版（Blackboard）** = 树里所有节点共享的**键/值存储**
> - **黑版的一条记录（entry）** = 一个**键/值对**
> - **Input port（输入端口）** 从黑版读数据，**Output port（输出端口）** 往黑版写数据

**图示：**

```
                   黑版 (Blackboard)
          ┌──────────────────────────┐
          │  "the_answer" = "42"     │
          │  "target"    = "bottle"  │
          │  "battery"   = 85        │
          └──────────────────────────┘
                ↕               ↕
          OutputPort         InputPort
          (写入)               (读取)
      ThinkWhatToSay       SaySomething
```

## 三、Input ports（输入端口）

**原文说：**
> 输入可以有两种：
> 1. **静态字符串**：节点直接读这个字符串
> 2. **黑版引用**：用 `{key}` 语法指向黑版里的某条记录

**XML 示例：**

```xml
<!-- 静态字符串：直接传 "hello world" -->
<SaySomething name="first"   message="hello world"/>

<!-- 黑版引用：从黑版里读 key 为 "greetings" 的值 -->
<SaySomething name="second"  message="{greetings}"/>
```

**C++ 实现一个有端口的节点：**

```cpp
class SaySomething : public SyncActionNode
{
public:
  // 有端口的节点，必须用这个构造函数签名！
  SaySomething(const std::string& name, const NodeConfig& config)
    : SyncActionNode(name, config)
  {}

  // ❗必须定义这个静态方法：声明端口
  static PortsList providedPorts()
  {
    // 声明：这个节点有一个输入端口，叫 "message"，类型是 std::string
    return { InputPort<std::string>("message") };
  }

  // tick() 时从端口读数据
  NodeStatus tick() override
  {
    // getInput<T>("端口名") 返回一个 Expected<T>
    Expected<std::string> msg = getInput<std::string>("message");

    // 检查读取是否成功
    if (!msg)
    {
      // 失败了就抛异常或返回 FAILURE
      throw RuntimeError("missing required input [message]: ", msg.error());
    }

    // .value() 取出实际值
    std::cout << "Robot says: " << msg.value() << std::endl;
    return NodeStatus::SUCCESS;
  }
};
```

**我的解释：几个关键点**

**1. 构造函数变了**

```
教程 01：ApproachObject(const std::string& name)
教程 02：SaySomething(const std::string& name, const NodeConfig& config)
                                          ^^^^^^^^^^^^^^^^^^^^^^^^^^
```

有端口的节点必须接收 `NodeConfig`，因为端口信息是从 XML 解析出来的，通过 `NodeConfig` 传给节点。

**2. `providedPorts()` 是静态方法**

它在编译时就确定"这个节点有哪些端口、什么类型"，但端口"连到黑版的哪个 key"是运行时 XML 决定的。

**3. getInput() 必须在 tick() 里调用，不能在构造函数里**

原文强调了这一点：

> ⚠️ **强烈建议**：`getInput()` 在 `tick()` 里调用，不要在构造函数里。因为输入的值可能在运行时变化。

```cpp
// 正确：每次 tick 都重新读
NodeStatus tick() override {
  auto msg = getInput<std::string>("message");
  // ...
}

// 错误：构造函数只读一次，后面黑版的值变了也不知道
ThinkWhatToSay(...) {
  auto msg = getInput<std::string>("message");  // ❌ 别这么写
}
```

## 四、Output ports（输出端口）

**原文的示例——写入黑版的节点：**

```cpp
class ThinkWhatToSay : public SyncActionNode
{
public:
  ThinkWhatToSay(const std::string& name, const NodeConfig& config)
    : SyncActionNode(name, config)
  {}

  static PortsList providedPorts()
  {
    // 声明一个输出端口，叫 "text"，类型 std::string
    return { OutputPort<std::string>("text") };
  }

  NodeStatus tick() override
  {
    // 写入黑版：key 是 "text"，值是 "The answer is 42"
    setOutput("text", "The answer is 42");
    return NodeStatus::SUCCESS;
  }
};
```

**我的解释：**

`setOutput("端口名", 值)` 往黑版里写数据。XML 里通过 `text="{the_answer}"` 把端口连到黑版的 `the_answer` 这个 key。

**另外，原文提到了一个内置 Action `Script`，可以直接在 XML 里写黑版：**

```xml
<Script code=" the_answer:='The answer is 42' " />
```

等价于 C++ 里调用 `setOutput("text", "The answer is 42")`，但不需要写 C++ 代码。适合调试和简单场景。

> 注意：`:=` 是 BT.CPP 4.x 的赋值语法。

## 五、Bidirectional ports（双向端口）

**原文：**
> 如果节点需要**同时读写**黑版里的值，用 `BidirectionalPort<T>`。

```cpp
static PortsList providedPorts()
{
    return {
        BidirectionalPort<std::vector<int>>("vector"),
        InputPort<int>("value")
    };
}
```

**我的解释：**

```
InputPort<T>     → 只读（getInput）
OutputPort<T>    → 只写（setOutput）
BidirectionalPort<T> → 可读可写（getInput + setOutput / getLockedPortContent）
```

双向端口通常用 `getLockedPortContent()` 做线程安全的读写，进阶内容在后来的教程 13 讲。

## 六、完整示例

**XML：**

```xml
<root BTCPP_format="4">
    <BehaviorTree ID="MainTree">
       <Sequence name="root_sequence">
           <!-- 第1步：直接传静态字符串 -->
           <SaySomething     message="hello"/>

           <!-- 第2步：往黑版写入 "the_answer" -->
           <ThinkWhatToSay   text="{the_answer}"/>

           <!-- 第3步：从黑版读取 "the_answer" -->
           <SaySomething     message="{the_answer}"/>
       </Sequence>
    </BehaviorTree>
</root>
```

**执行流程：**

```
第1步：SaySomething   → 打印 "hello"
                          ↓
第2步：ThinkWhatToSay → setOutput("text", "The answer is 42")
                        → 黑版["the_answer"] = "The answer is 42"
                          ↓
第3步：SaySomething   → getInput("message") 从黑版读
                        → 打印 "The answer is 42"
```

**黑版的变化过程：**

```
开始时：
  黑版 = {}

第1步后：
  黑版 = {}

第2步后：
  黑版 = { "the_answer": "The answer is 42" }

第3步后：
  黑版 = { "the_answer": "The answer is 42" }
  (SaySomething 读取它)
```

**关键：XML 里 `text="{the_answer}"` 和 `message="{the_answer}"` 引用了黑版里同一个 key。**

```
ThinkWhatToSay 的 text 端口（输出）──→ 黑版["the_answer"] ←── SaySomething 的 message 端口（输入）

  C++ 声明：                    XML 连接：
  OutputPort<string>("text")    text="{the_answer}"
  InputPort<string>("message")  message="{the_answer}"
```

## 七、类型安全

**原文末尾特别提到：**

> 输出端口和输入端口通过相同的 key（`the_answer`）连接。它们的类型必须一样，都是 `std::string`。如果类型不一致，`factory.createTreeFromFile()` 会抛异常。

```cpp
// 如果 ThinkWhatToSay 声明了 OutputPort<int>("text")
// 而 SaySomething 声明了 InputPort<std::string>("message")
// 运行时直接报错，类型不匹配！✅ 这就是类型安全
```

## 八、这篇在学什么

| 概念 | 对应代码 |
|---|---|
| 声明输入端口 | `InputPort<std::string>("message")` |
| 在 tick 里读输入 | `getInput<std::string>("message")` |
| 声明输出端口 | `OutputPort<std::string>("text")` |
| 在 tick 里写输出 | `setOutput("text", "The answer is 42")` |
| XML 引用黑版 | `message="{the_answer}"` |
| 构造函数签名 | `(const string& name, const NodeConfig& config)` |
| 有端口必须加 `providedPorts()` | `static PortsList providedPorts()` |
| 类型安全 | 端口类型不匹配 → 运行时报错 |

## 跟教程 01 的区别

```
教程 01：节点不需要数据交换
  class ApproachObject : public SyncActionNode {
    ApproachObject(const std::string& name)
      : SyncActionNode(name, {})     // {} = 没有端口
    {}
  };

教程 02：节点通过黑版交换数据
  class SaySomething : public SyncActionNode {
    SaySomething(const std::string& name, const NodeConfig& config)
      : SyncActionNode(name, config)   // config = 有端口
    {}
    static PortsList providedPorts() {  // 声明端口
      return { InputPort<std::string>("message") };
    }
  };
```

**一句话总结：**
> 教程 01 教你怎么让节点"动起来"，教程 02 教你怎么让节点之间"传数据"。
