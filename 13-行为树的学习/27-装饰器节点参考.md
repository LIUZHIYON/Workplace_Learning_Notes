# Decorators 逐段解释

> 来源：https://behaviortree.dev/docs/nodes-library/DecoratorNode
> 说明：这是 Nodes Library 里的**装饰器完整参考**。BT.CPP 内置的所有装饰器都列在这里。

---

## 一、什么是 Decorator

**原文：**
> 装饰器（Decorator）是一个必须有且只有一个子节点的节点。由它决定**是否需要、什么时候、多少次**去 tick 子节点。

---

## 二、所有内置装饰器一览

### 2.1 Inverter（取反）

**行为：**
- 子节点 SUCCESS → 返回 **FAILURE**
- 子节点 FAILURE → 返回 **SUCCESS**
- 子节点 RUNNING → 返回 **RUNNING**（透传）

```xml
<Inverter>
    <IsDoorClosed/>
</Inverter>
<!-- 门关着 → IsDoorClosed SUCCESS → Inverter 输出 FAILURE -->
```

---

### 2.2 ForceSuccess / ForceFailure（强制结果）

**行为：**
- 子节点 SUCCESS/FAILURE → 强制输出 **SUCCESS**（或 **FAILURE**）
- 子节点 RUNNING → 透传 RUNNING

```xml
<ForceSuccess>
    <SomeNodeThatMightFail/>
</ForceSuccess>
<!-- 不管子节点成功还是失败，都返回 SUCCESS -->
```

---

### 2.3 Repeat（重复 N 次）

| 端口 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `num_cycles` | InputPort\<int\> | 必填 | 重复次数，`-1` 表示无限循环 |

**行为：**
- 子节点 SUCCESS → 计数器+1，继续下一轮
- 子节点 FAILURE → **立即返回 FAILURE**（中断循环）
- 子节点 RUNNING → **不计数**，下一 tick 继续等
- 全部 N 次完成后 → 返回 **SUCCESS**

```xml
<Repeat num_cycles="3">
    <ClapYourHandsOnce/>
</Repeat>
```

---

### 2.4 RetryUntilSuccessful（重试直到成功）

| 端口 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `num_attempts` | InputPort\<int\> | 必填 | 最大尝试次数，`-1` 表示无限重试 |

**行为：**
- 子节点 SUCCESS → **立即返回 SUCCESS**（中断重试）
- 子节点 FAILURE → 计数器+1，继续重试
- 子节点 RUNNING → **不计数**，下一 tick 继续等
- 全部 N 次失败后 → 返回 **FAILURE**

```xml
<RetryUntilSuccessful num_attempts="3">
    <OpenDoor/>
</RetryUntilSuccessful>
```

**Repeat vs RetryUntilSuccessful：**

| 特性 | Repeat | RetryUntilSuccessful |
|---|---|---|
| 循环条件 | 一直成功就继续 | 一直失败就继续 |
| 中断条件 | 失败时中断 | 成功时中断 |
| 成功条件 | N 次全部完成 | 任意一次成功 |
| 失败条件 | 任意一次失败 | N 次全部失败 |

---

### 2.5 KeepRunningUntilFailure（一直跑直到失败）

**行为：**
- 子节点 SUCCESS → 返回 **RUNNING**（继续跑）
- 子节点 FAILURE → 返回 **FAILURE**（结束）
- 子节点 RUNNING → 返回 RUNNING

翻译成人话：**"不断重复执行子节点，直到它失败才停。"**

---

### 2.6 Delay（延迟后执行）

**行为：**
- 从节点被 tick 开始计时
- 在 `delay_msec` 毫秒**之前**返回 RUNNING
- 到达延迟时间后才真正 tick 子节点

```xml
<Delay delay_msec="2000">
    <FireMissile/>
</Delay>
<!-- 2 秒后才执行 FireMissile -->
```

**Timeout vs Delay：**

> Delay 是**执行前**等一段时间；Timeout 是**执行中**超时中断。

---

### 2.7 Timeout（超时中断）

| 端口 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `msec` | InputPort\<unsigned\> | 必填 | 超时时间 |

**行为：**
- 子节点在超时前完成 → 返回子节点的结果
- 子节点超时了还在 RUNNING → **halt 子节点，返回 FAILURE**

```xml
<Timeout msec="5000">
    <KeepYourBreath/>
</Timeout>
```

**官方推荐：Timeout + RetryUntilSuccessful 组合——重试+超时：**

```xml
<RetryUntilSuccessful num_attempts="3">
    <Timeout msec="5000">
        <LongRunningAction/>
    </Timeout>
</RetryUntilSuccessful>
<!-- 每次重试最多等 5 秒，3 次都超时就返回 FAILURE -->
```

---

### 2.8 RunOnce（只执行一次）

**行为：**
- 第一次 tick 时正常执行子节点
- 子节点完成后（SUCCESS/FAILURE），后续 tick **直接 SKIPPED**（跳过）

| 端口 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `then_skip` | InputPort\<bool\> | true | true=跳过，false=永远返回子节点同样的结果 |

```xml
<RunOnce>
    <InitializeSensors/>
</RunOnce>
<!-- 只在第一次 tick 初始化传感器，后续跳过 -->
```

---

### 2.9 Precondition（前置条件装饰器）

**已在 21-前置后置条件指南里详细讲过了，这里只列要点：**

| 端口 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `if` | InputPort\<string\> | 必填 | 脚本条件 |
| `else` | InputPort\<NodeStatus\> | FAILURE | 条件不满足时返回的状态 |

```xml
<Precondition if="battery_level > 20" else="FAILURE">
    <MoveToGoal/>
</Precondition>
```

**`else="RUNNING"` 的特殊用法：** 条件不满足时返回 RUNNING 而不是 FAILURE，这样树会继续 tick，条件恢复时自动继续执行子节点。适合**需要实时监控**的场景。

## 三、其他需要 C++ 注册的装饰器

### 3.1 ConsumeQueue（消费队列）

从队列中消费数据，空队列返回 SUCCESS。

```cpp
factory.registerNodeType<ConsumeQueue<Pose2D>>("ConsumeQueue");
```

### 3.2 SimpleDecoratorNode（快速注册简单装饰器）

用函数指针方式注册装饰器，不需要写完整的类：

```cpp
factory.registerSimpleDecorator("MyDecorator",
    [](NodeStatus prev_status, TreeNode& node) -> NodeStatus {
        // prev_status = 子节点返回的状态
        // 你可以在这里决定最终返回什么
        return NodeStatus::SUCCESS;
    },
    PortsList{} // 端口声明
);
```
