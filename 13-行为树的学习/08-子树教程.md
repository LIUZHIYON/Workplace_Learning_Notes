# Tutorial 05: Using SubTrees 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_05_subtrees
> 说明：这篇教你怎么用 **SubTree（子树）** 把多个行为树组合在一起，实现**层次化的行为树**。

---

## 一、引入

**原文大意：**
> 我们可以通过把小型的可复用行为树嵌入到更大的树中，来构建大规模的行为树。
> 
> 换句话说，我们想要创建**层次化**的行为树，让树变得**可组合**。
> 
> 方法：在 XML 里定义多棵树，用 **`<SubTree>`** 节点把一棵树包含到另一棵树里。

**我的解释：**

```
之前：一棵树里把所有节点全部列出来
  一个大 Sequence 塞几十个节点 → 难维护、不可复用

现在：拆分成多个小树
  MainTree（主逻辑）
    ├── 条件检查
    └── SubTree ID="开门流程"    ← 复用！
         └── 里面是开门的具体步骤
```

---

## 二、示例场景：CrossDoor（穿门）

原文灵感来自一篇流行的游戏开发文章。场景是这样的：

```
你站在一扇门前，要穿过去。
如果门开着 → 直接穿过去。
如果门关着：
  先试试开门（OpenDoor）
  开门失败 → 尝试撬锁，最多 5 次（PickLock）
  撬锁失败 → 把门砸了（SmashDoor）
```

**画成树（原文的 SVG 图）：**

```
                    MainTree
                    Sequence
              ┌───────┴────────┐
           Fallback          PassThroughDoor
      ┌──────┴────────┐
   Inverter         SubTree
      │              ID="DoorClosed"
   IsDoorClosed


                DoorClosed (子树)
                  Fallback
          ┌───────┼────────┐
       OpenDoor  Retry*5  SmashDoor
                   │
                PickLock
```

## 三、XML 代码

```xml
<root BTCPP_format="4">

    <!-- 主树 -->
    <BehaviorTree ID="MainTree">
        <Sequence>
            <Fallback>
                <Inverter>
                    <IsDoorClosed/>
                </Inverter>
                <SubTree ID="DoorClosed"/>          <!-- ← 引用子树！ -->
            </Fallback>
            <PassThroughDoor/>
        </Sequence>
    </BehaviorTree>

    <!-- 子树定义 -->
    <BehaviorTree ID="DoorClosed">
        <Fallback>
            <OpenDoor/>
            <RetryUntilSuccessful num_attempts="5">
                <PickLock/>
            </RetryUntilSuccessful>
            <SmashDoor/>
        </Fallback>
    </BehaviorTree>

</root>
```

**我的逐层解释：**

**第 1 层：`MainTree` 的逻辑**

```
Sequence（按顺序）：
  ① Fallback（二选一）：
     尝试 A：Inverter(IsDoorClosed) → 门没关？→ 直接过
     尝试 B：SubTree("DoorClosed")  → 门关了 → 进去处理
  ② PassThroughDoor → 穿过去
```

**第 2 层：`DoorClosed` 子树的逻辑**

```
Fallback（三选一）：
  尝试 1：OpenDoor         → 直接开门
  尝试 2：Retry*5(PickLock) → 撬锁，最多 5 次
  尝试 3：SmashDoor        → 砸门（肯定成功）
```

**第 3 层：Decorator 的作用**

```
Inverter(IsDoorClosed)
  → IsDoorClosed 返回 SUCCESS（门关了）→ Inverter 变成 FAILURE
  → IsDoorClosed 返回 FAILURE（门没关）→ Inverter 变成 SUCCESS
```

所以：
- 门没关（FAILURE）→ Inverter 变成 SUCCESS → Fallback 直接成功 → 跳过了 SubTree → 直接 PassThroughDoor
- 门关了（SUCCESS）→ Inverter 变成 FAILURE → Fallback 尝试 B（DoorClosed 子树）

## 四、执行流程

```
场景 1：门是开的

  tick → MainTree
    → Sequence
      → Fallback
        → Inverter(IsDoorClosed) → IsDoorClosed 返回 FAILURE（门没关）
          → Inverter 取反 → SUCCESS ✅
        → Fallback 直接成功 ✅（不执行 SubTree）
      → PassThroughDoor → SUCCESS ✅
    → Sequence SUCCESS ✅
```

```
场景 2：门是关的但能打开

  tick → MainTree
    → Sequence
      → Fallback
        → Inverter(IsDoorClosed) → SUCCESS → FAILURE ❌
        → SubTree("DoorClosed")
          → Fallback
            → OpenDoor → SUCCESS ✅（门开了）
          → Fallback SUCCESS ✅
        → Fallback SUCCESS ✅
      → PassThroughDoor → SUCCESS ✅
    → Sequence SUCCESS ✅
```

```
场景 3：门锁了，撬 3 次打开

  tick → MainTree
    → Fallback
      → Inverter → FAILURE ❌
      → SubTree("DoorClosed")
        → Fallback
          → OpenDoor → FAILURE ❌（门锁了）
          → RetryUntilSuccessful
            → PickLock → FAILURE ❌
            → PickLock → FAILURE ❌
            → PickLock → SUCCESS ✅（第 3 次打开了）
          → Retry SUCCESS ✅
        → Fallback SUCCESS ✅
      → PassThroughDoor → SUCCESS ✅
```

```
场景 4：门又锁又撬不开，最后砸门

  → SubTree("DoorClosed")
    → Fallback
      → OpenDoor → FAILURE ❌
      → Retry*5(PickLock) → 5 次全 FAILURE ❌
      → SmashDoor → SUCCESS ✅（砸门肯定开）
    → Fallback SUCCESS ✅
```

## 五、C++ 注册代码

**原文只展示了 `registerNodes` 部分（其他 Action 实现略过）：**

```cpp
class CrossDoor
{
public:
    void registerNodes(BT::BehaviorTreeFactory& factory);

    // 各个 Action/Condition 的实现
    BT::NodeStatus isDoorClosed();
    BT::NodeStatus passThroughDoor();
    BT::NodeStatus pickLock();
    BT::NodeStatus openDoor();
    BT::NodeStatus smashDoor();

private:
    bool _door_open   = false;
    bool _door_locked = true;
    int  _pick_attempts = 0;
};

void CrossDoor::registerNodes(BT::BehaviorTreeFactory &factory)
{
  // 注册条件节点
  factory.registerSimpleCondition(
      "IsDoorClosed", std::bind(&CrossDoor::isDoorClosed, this));

  // 注册动作节点
  factory.registerSimpleAction(
      "PassThroughDoor", std::bind(&CrossDoor::passThroughDoor, this));
  factory.registerSimpleAction(
      "OpenDoor", std::bind(&CrossDoor::openDoor, this));
  factory.registerSimpleAction(
      "PickLock", std::bind(&CrossDoor::pickLock, this));
  factory.registerSimpleCondition(
      "SmashDoor", std::bind(&CrossDoor::smashDoor, this));
}
```

**main 函数跟之前不一样的地方——有两个重要变化：**

```cpp
int main()
{
  BehaviorTreeFactory factory;
  CrossDoor cross_door;
  cross_door.registerNodes(factory);

  // ↓↓↓ 不同点 1：先注册 XML，再指定 ID 创建树 ↓↓↓
  factory.registerBehaviorTreeFromText(xml_text);
  auto tree = factory.createTree("MainTree");   // ← 指定主树的 ID

  // 打印树的递归结构（调试用）
  printTreeRecursively(tree.rootNode());

  tree.tickWhileRunning();
  return 0;
}
```

**区别对比：**

| 之前（单棵树） | 现在（多棵树） |
|---|---|
| `factory.createTreeFromText(xml)` | `factory.registerBehaviorTreeFromText(xml)` |
| 直接创建树 | 先注册所有树到 factory |
| — | `factory.createTree("ID")` 按 ID 取特定树 |

**为什么？** 因为现在 XML 里有**多棵** `<BehaviorTree>`，factory 需要先注册整个文件，然后你指定要创建哪一棵。

## 六、关于 SubTree 的关键点

### 6.1 SubTree 是一个 ControlNode

```
<SubTree ID="DoorClosed"/>  ← 相当于一个控制节点
```

它的子节点只有 1 个——就是被引用的树的**根节点**。

### 6.2 子树会携带自己的黑版

每个 SubTree 可以有自己的黑版。默认情况下：

```
MainTree 的黑版（父）
  └── DoorClosed 子树的黑版（子，可以跟父共享或独立）
```

这涉及**端口映射（Port Remapping）**，下一篇教程 06 会详细讲。

### 6.3 子树的好处

| 好处 | 说明 |
|---|---|
| **代码复用** | "开门"流程只需要写一次 XML |
| **层次清晰** | 主树 10 行，每棵子树专注自己的事 |
| **独立测试** | 每棵子树可以单独创建和测试 |
| **模块化** | 不同团队可以写不同的子树 |
