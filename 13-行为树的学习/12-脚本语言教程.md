# Tutorial 09: Scripting example 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_09_scripting
> 说明：这篇介绍 **Script（脚本）节点**和 **Precondition（前置条件）节点**——让你在 XML 里直接做变量赋值和条件判断，不用写 C++ 代码。

---

## 一、Script 节点

**原文大意：**
> 在 BT.CPP 4.x 的脚本语言里，变量就是黑版的 entry。支持的类型包括：数字（整数和浮点数）、字符串、和注册过的枚举值。

**示例——用 `<Script>` 往黑版赋值：**

```xml
<Script code=" msg:='hello world' "/>
<Script code=" A:=THE_ANSWER; B:=3.14; color:=RED "/>
```

**我的解释：**

| 脚本代码 | 效果 |
|---|---|
| `msg:='hello world'` | 黑版 `msg` = 字符串 "hello world" |
| `A:=THE_ANSWER` | 黑版 `A` = 整数 42（THE_ANSWER 是注册的别名）|
| `B:=3.14` | 黑版 `B` = 浮点数 3.14 |
| `color:=RED` | 黑版 `color` = 枚举值 RED（=1） |

**赋值语法的区别：**

```
=  用在 XML 属性里：message="hello"
:= 用在 Script 脚本里：msg:='hello world'
```

## 二、Precondition 节点

**原文示例：**

```xml
<Precondition if="A>B && color != BLUE" else="FAILURE">
    <Sequence>
        <SaySomething message="{A}"/>
        <SaySomething message="{B}"/>
        <SaySomething message="{msg}"/>
        <SaySomething message="{color}"/>
    </Sequence>
</Precondition>
```

**我的解释：**

`Precondition` 是一个**带条件的装饰器**：

```
<Precondition if="条件" else="FAILURE">
  ...子节点...
</Precondition>
```

**执行逻辑：**
```
条件成立？→ 执行子节点 → 返回子节点的结果
条件不成立？→ 不执行子节点 → 返回 else 里指定的值（FAILURE / SUCCESS / RUNNING）
```

具体到上面这个例子：

```
if A>B && color != BLUE
→ 42 > 3.14 → true
→ color = RED（=1），BLUE = 2 → RED != BLUE → true
→ true && true → true ✅

所以条件成立，执行子节点 Sequence
```

## 三、输出结果

**执行后打印：**

```
Robot says: 42.000000
Robot says: 3.140000
Robot says: hello world
Robot says: 1.000000
```

**对应关系：**

| 黑版变量 | 值 | 打印 |
|---|---|---|
| `A` | 42 | `42.000000` |
| `B` | 3.14 | `3.140000` |
| `msg` | "hello world" | `hello world` |
| `color` | RED = 1 | `1.000000` |

**注意：** `SaySomething` 的端口类型是 `std::string`，数字传进去会被转成字符串，所以浮点数显示 `42.000000` 而不是 `42`。

## 四、完整的 C++ 代码

```cpp
enum Color { RED = 1, BLUE = 2, GREEN = 3 };

int main()
{
  BehaviorTreeFactory factory;
  factory.registerNodeType<DummyNodes::SaySomething>("SaySomething");

  // 把 C++ 枚举类型注册到脚本语言里
  factory.registerScriptingEnums<Color>();

  // 手动注册一个别名（超出 magic_enum 默认范围 [-128,128] 时用这个）
  factory.registerScriptingEnum("THE_ANSWER", 42);

  auto tree = factory.createTreeFromText(xml_text);
  tree.tickWhileRunning();

  return 0;
}
```

**两个注册脚本枚举的方法：**

| 方法 | 代码 | 适用场景 |
|---|---|---|
| **批量注册整个枚举** | `factory.registerScriptingEnums<Color>()` | Color 的所有值（RED/BLUE/GREEN）都能在脚本里用 |
| **单个注册别名** | `factory.registerScriptingEnum("THE_ANSWER", 42)` | 任何整数值，不受枚举范围限制 |

## 五、脚本表达式语法参考

**支持的运算符和语法（原文指向了更详细的 Scripting Guide）：**

| 运算 | 示例 |
|---|---|
| 赋值 | `x:=42` 或 `msg:='hello'` |
| 算术 | `+ - * /` |
| 比较 | `> < >= <= == !=` |
| 逻辑 | `&& \|\| !` |
| 括号 | `( )` |
| 字符串 | 用单引号 `'hello'` |

**注意：** 脚本里使用 `:=` 而不是 `=`。`=` 在 XML 文件里是属性赋值，`:=` 是脚本赋值。

## 六、Precondition vs ConditionNode 的区别

| | Precondition（脚本方式） | ConditionNode（C++ 方式） |
|---|---|---|
| 在哪定义 | XML 里用 `if="..."` 写条件 | 用 C++ 继承 ConditionNode 写 tick() |
| 修改条件 | 改 XML 就行，不用重编译 | 要改 C++ 再编译 |
| 复杂度 | 适合简单条件 | 适合复杂逻辑 |
| 是否需要 C++ | ❌ 不需要 | ✅ 需要 |
| 适用场景 | 快速调试、原型验证 | 正式项目 |

**Precondition 推荐用于：** 快速验证、原型阶段、调试。正式项目里条件复杂时还是推荐写 ConditionNode。

## 七、完整 XML 执行流程

```xml
<Sequence>
    <Script code=" msg:='hello world' "/>
    <Script code=" A:=THE_ANSWER; B:=3.14; color:=RED "/>
    <Precondition if="A>B && color != BLUE" else="FAILURE">
        <Sequence>
            <SaySomething message="{A}"/>
            <SaySomething message="{B}"/>
            <SaySomething message="{msg}"/>
            <SaySomething message="{color}"/>
        </Sequence>
    </Precondition>
</Sequence>
```

**执行步骤：**
```
Step 1: Script → 黑版 msg = "hello world"
Step 2: Script → 黑版 A=42, B=3.14, color=1(RED)
Step 3: Precondition
          → 条件 A>B && color!=BLUE → true
          → 执行子 Sequence
            → SaySomething → 打印 42.000000
            → SaySomething → 打印 3.140000
            → SaySomething → 打印 hello world
            → SaySomething → 打印 1.000000
          → 返回 SUCCESS
Step 4: Sequence → SUCCESS
```

---

**一句话总结：**
> `<Script>` 让你在 XML 里直接往黑版赋值（不用写 C++），`<Precondition>` 让你在 XML 里写条件来决定是否执行子树。两个都是**调试和原型阶段的利器**，正式项目建议还是用 ConditionNode 更好维护。
