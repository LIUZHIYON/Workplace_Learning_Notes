# Tutorial 06: Port Remapping 逐段解释

> 来源：https://behaviortree.dev/docs/tutorial-basics/tutorial_06_subtree_ports
> 说明：上一篇教程学了 SubTree，这篇讲怎么**在父树和子树之间传递数据**——也就是**端口重映射（Port Remapping）**。

---

## 一、问题背景

**原文大意：**
> 在 CrossDoor 例子里，从父树角度看，`<SubTree>` 看起来就像一个叶子节点。
> 
> 为了避免大型树里的**命名冲突**，每棵树和子树都使用各自的**黑版实例**。
> 
> 因此，我们需要**显式地连接**父树的端口和子树的端口。
> 
> 这项工作**完全在 XML 里完成**，不需要修改 C++ 代码。

**我的解释：**

```
问题：为什么需要 remap？

假设你有两棵子树都需要用到 "target" 这个 key：
  MainTree 的黑版：  target = (1, 2, 3)
  子树A 的黑版：     target = ???       ← 子树有自己的黑版！
  子树B 的黑版：     target = ???       ← 跟父树的 target 不是同一个！

如果不做 remap，子树里的 target 是它自己黑版里的，跟父树没关系。
```

**每棵子树都有自己的黑版：**

```
MainTree（黑版 1）
  └── SubTree "MoveRobot"（黑版 2 — 独立！）
  └── SubTree "MoveRobot"（黑版 3 — 另一个实例！）
```

这样就避免了命名冲突——不同的子树可以用同名的 key，互不影响。

## 二、XML 中的端口重映射

**原文的示例：**

```xml
<root BTCPP_format="4">

    <BehaviorTree ID="MainTree">
        <Sequence>
            <!-- 往主树黑版写入 move_goal -->
            <Script code=" move_goal='1;2;3' "/>

            <!-- SubTree 的 target 端口映射到父树的 move_goal -->
            <SubTree ID="MoveRobot"
                     target="{move_goal}"          <!-- 输入：父→子 -->
                     result="{move_result}"/>      <!-- 输出：子→父 -->

            <!-- 从主树黑版读取 move_result -->
            <SaySomething message="{move_result}"/>
        </Sequence>
    </BehaviorTree>

    <!-- 子树定义 -->
    <BehaviorTree ID="MoveRobot">
        <Fallback>
            <Sequence>
                <MoveBase  goal="{target}"/>       <!-- 从子树自己黑版读 -->
                <Script code=" result:='goal reached' "/>
            </Sequence>
            <ForceFailure>
                <Script code=" result:='error' "/>
            </ForceFailure>
        </Fallback>
    </BehaviorTree>

</root>
```

**关键行：**

```xml
<SubTree ID="MoveRobot"
         target="{move_goal}"     <!-- 子树端口 = {父树黑版 key} -->
         result="{move_result}"/> <!-- 子树端口 = {父树黑版 key} -->
```

**翻译：**
> 把子树 `MoveRobot` 的 `target` 端口连接到父树黑版的 `move_goal` 这个 key。
> 把子树 `MoveRobot` 的 `result` 端口连接到父树黑版的 `move_result` 这个 key。

## 三、数据流向示意图

```
            MainTree 的黑版
    ┌────────────────────────────────┐
    │  "move_goal"  = Pose2D(1,2,3) │  ← Script 写入
    │  "move_result" = ???          │  ← 等着子树填
    └─────────┬──────────────────────┘
              │ remap
              │
              ▼
    ┌──────────────────┐
    │ SubTree "MoveRobot" 的黑版    │
    │  "target" = 映射到 move_goal  │
    │  "result" = 映射到 move_result│
    └──────────────────┘
              │
              ▼ 子树内部使用
    <MoveBase goal="{target}"/>     ← 读取 target
    <Script code="result:='...'"/>  ← 写入 result（会同步到父树）
```

**执行流程：**

```
第1步：MainTree → Script → 写入 move_goal = (1, 2, 3)

第2步：MainTree → SubTree("MoveRobot")
          ↓ remap
       MoveRobot 内部
          → MoveBase goal="{target}" → 读到的值是 (1, 2, 3)
          → Script result:='goal reached'
          → 子树返回 SUCCESS
          ↓ remap （反向同步）
          move_result = "goal reached"

第3步：MainTree → SaySomething message="{move_result}"
          → 打印 "goal reached"
```

## 四、C++ 代码——黑版调试

**原文展示了一个调试技巧：用 `debugMessage()` 查看黑版内容：**

```cpp
int main()
{
  BT::BehaviorTreeFactory factory;
  factory.registerNodeType<SaySomething>("SaySomething");
  factory.registerNodeType<MoveBaseAction>("MoveBase");

  factory.registerBehaviorTreeFromText(xml_text);
  auto tree = factory.createTree("MainTree");

  tree.tickWhileRunning();

  // 打印主树黑版
  std::cout << "\n------ First BB ------";
  tree.subtrees[0]->blackboard->debugMessage();

  // 打印子树黑版
  std::cout << "\n------ Second BB------";
  tree.subtrees[1]->blackboard->debugMessage();

  return 0;
}
```

**输出：**

```
------ First BB ------
move_result (std::string)
move_goal (Pose2D)

------ Second BB------
[result] remapped to port of parent tree [move_result]
[target] remapped to port of parent tree [move_goal]
```

**这告诉我们：**
- `tree.subtrees[0]` = MainTree 的黑版 → 有 `move_result` 和 `move_goal`
- `tree.subtrees[1]` = MoveRobot 子树的黑版 → `result` 和 `target` 端口都标记为"已 remap 到父树"

## 五、默认的端口映射规则

**原文没有直接列出，但从代码中可以总结出：**

| 场景 | 行为 | 写法 |
|---|---|---|
| 子树的端口名跟父树黑版 key 名**相同** | 自动匹配，不需要显式 remap | — |
| 子树的端口名跟父树黑版 key 名**不同** | 需要显式 remap | `target="{move_goal}"` |
| 子树端口不需要跟父树通信 | 不用在 `<SubTree>` 属性里写 | 略过即可 |

**显式 remap 语法：**

```
<SubTree ID="子树名" 子树端口名="{父树黑版key}"/>
```

**对于输出端口也一样：**

```
<SubTree ID="子树名" 子树输出端口名="{父树黑版key}"/>
```

## 六、为什么需要这种机制（用一个对比说明）

### 没有 remap 的代码（有问题）

```xml
<!-- 父树 -->
<BehaviorTree ID="MainTree">
    <Sequence>
        <Script code=" target='1;2' "/>
        <SubTree ID="SubA"/>
        <SubTree ID="SubB"/>
    </Sequence>
</BehaviorTree>

<!-- 子树 A -->
<BehaviorTree ID="SubA">
    <Action goal="{target}"/>   <!-- 这个 target 是子树自己黑版的 -->
</BehaviorTree>

<!-- 子树 B -->
<BehaviorTree ID="SubB">
    <Action goal="{target}"/>   <!-- 这个 target 也是子树自己黑版的 -->
</BehaviorTree>
```

`SubA` 和 `SubB` 各自的 `{target}` 都是**自己黑版里的空值**，父树的 `target` 传不进去！

### 有 remap 的代码（正确）

```xml
<BehaviorTree ID="MainTree">
    <Sequence>
        <Script code=" target='1;2' "/>
        <SubTree ID="SubA" goal="{target}"/>
        <SubTree ID="SubB" goal="{target}"/>
    </Sequence>
</BehaviorTree>
```

这样 `SubA` 的 `goal` 端口和 `SubB` 的 `goal` 端口都正确映射到了父树的 `target`。

**一句话总结：**
> 每棵子树有自己的黑版，通过 `<SubTree 端口名="{父树黑版key}">` 的语法来 remap，把子树端口"接线"到父树的黑版。这样子树的输入输出就跟父树连通了，而且不同子树间的同名 key 不会冲突。
