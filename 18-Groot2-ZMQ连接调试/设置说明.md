## 连接流程

### 1. 板子上跑一个 ZMQ 服务器

SSH 到板子，启动 `groot2_server.py`（在 `~/groot2_bridge/` 里）：

```bash
ssh cat@192.168.1.70
cd ~/groot2_bridge
pkill -f 'groot2_server'        # 杀掉旧的
nohup python3 -u groot2_server.py > /tmp/g2.log 2>&1 &  # 启动新的
```

这个程序做的事情：
- 每 100ms tick 一次行为树（检查提醒→TTS→播报→通知）
- 监听端口 **1667**，等 BehaviorTreeMonitor 来连接
- 收到 FULLTREE 请求 → 返回行为树 XML
- 收到 STATUS 请求 → 返回节点当前状态
- 收到 BLACKBOARD 请求 → 返回黑板变量

### 2. Windows 上启动 BehaviorTreeMonitor

```bash
cd E:\LuBanCat\BT_ros2\BehaviorTreeMonitor
python main.py
```

这会打开一个 Qt 窗口，里面是个网页界面。

### 3. 填 Host/Port 点 Connect

在网页界面里：

| 字段 | 值 |
|------|-----|
| **Host** | `192.168.1.70` |
| **Port** | `1667` |

点 **Connect**。

### 为什么会断连？

BehaviorTreeMonitor 发的是 **2部分消息**（header + payload），但服务器原来只读了 **1部分**。第2部分卡在缓冲区，导致 ZMQ 死锁。我改了两处：

1. **收消息时把多余部分吃掉** — 确保 socket 状态干净
2. **发消息出错时自动重建 socket** — 不死锁

### 如果连不上怎么办

```bash
# 1. 检查板子上端口是否在监听
ssh cat@192.168.1.70 "ss -tlnp | grep 1667"

# 2. 如果没监听，重启服务器
ssh cat@192.168.1.70 "cd ~/groot2_bridge && pkill -f groot2_server && nohup python3 -u groot2_server.py > /tmp/g2.log 2>&1 &"

# 3. 从 Windows 测试一下
python -c "import zmq,struct,time;ctx=zmq.Context();s=ctx.socket(zmq.REQ);s.setsockopt(zmq.RCVTIMEO,5000);s.connect('tcp://192.168.1.70:1667');h=struct.pack('<BBI',2,ord('T'),42);s.send_multipart([h,b'']);time.sleep(1);r=s.recv_multipart();print('OK parts=',len(r))"
```

如果输出了 `OK parts=2`，说明通了，去 BehaviorTreeMonitor 点 Connect 就行。
