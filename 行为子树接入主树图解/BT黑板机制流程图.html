🧠 BT.CPP 黑板（Blackboard）机制

子树隔离 · 端口映射 · 感知数据直写 · 完整数据流

① 什么是黑板？ 核心概念

黑板 = 公共便签墙
行为树的节点不直接传数据给对方，而是通过一个公共的键值对存储交换信息。

  • ✅ 任意节点都可以读黑板
  • ✅ 任意节点都可以写黑板
  • ✅ 键值对格式：变量名 → 值
  • ✅ 子树有自己独立的黑板

② 子树间的黑板隔离与映射 3.2

每个 SubTree 默认有自己的独立黑板，主黑板的变量不会自动流到子树里。 需要两种方式打通：

✅ 方式 A：自动映射

<!-- 声明 -->
<SubTree ID="DefaultMode" _autoremap="true"/>

同名端口自动绑定，省事但不灵活。

主黑板
touch_key
⇄
子黑板
touch_key
原理：子树端口若声明 touch_key="{touch_key}"， _autoremap 发现子黑板没有 touch_key，就去主黑板找同名的，自动连通。

🔧 方式 B：显式端口绑定

<!-- 显式映射 -->
<SubTree ID="IdleFallback"
         face_detected="{perception.face_detected}"/>

手动指定映射关系，灵活但要多写。

主黑板
perception.face_detected
→
子树的
face_detected
语法规则：
{变量名} → 从黑板读/写值
"常量" → 字面量，不走黑板
"" → 空字符串

③ 子树内部如何读写黑板 3.3

以 touch_behavior.xml 为例，节点通过 {变量名} 语法读写黑板：

<!-- ① 读：从黑板拿 touch_key -->
<TouchEdgeDetector touch_key="{touch_key}"/>

<!-- ② 写：GetConfigSync 内部 setOutput 把结果写回黑板 -->
<GetConfigSync command_key="{touch_key}"
               action_id="{action_id}"
               audio_path="{audio_path}"/>

<!-- ③ 读：从黑板拿 action_id 执行动作 -->
<ActionSync action_id="{action_id}"/>

④ 感知数据怎么进黑板？ 3.4

⚠️ 不走行为树！感知数据通过 ROS2 订阅回调直接写黑板，不需要等 tick 轮询。
// 语音识别结果 → 直接写黑板
voice_sub_ = ros_node_->create_subscription<std_msgs::msg::String>(
  "/robot_language_big_model/model_output", ...,
  [this](auto msg) {
    main_bb_->set("voice_text", msg->data);  // ← 收到消息立即写入
  });

// 提醒消息 → 直接写黑板
reminder_sub_ = ros_node_->create_subscription<std_msgs::msg::String>(
  "/robot/reminder", ...,
  [this](auto msg) {
    main_bb_->set("perception.reminder", msg->data);  // ← 直接写入
  });
