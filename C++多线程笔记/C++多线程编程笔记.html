先搞清楚：线程是什么？并发 vs 并行

🪡 线程 (Thread) —— 程序的"分身术"

想象你在厨房做饭：你一个人同时切菜、煮汤、烤面包——这在单线程下是不可能的， 你只能按顺序一件件做。但如果叫来三个帮手（线程），每个人负责一个任务，厨房就"并发"运转起来了。

在线程的世界里，所有线程共享同一个"厨房"（进程的地址空间、堆内存、全局变量）， 但每个线程有自己的"菜板"（栈、寄存器、程序计数器），互不干扰。

🏃 并发 Concurrency
一个 CPU 核心
快速交替处理多个任务
看起来"同时"，其实是"轮流"
VS
🚀 并行 Parallelism
多个 CPU 核心
真正同时执行多个任务
物理上的"同时"
💡 一句话总结：并发是"看起来一起做"，并行是"真的一起做"。 多线程可以在单核上实现并发，但要实现并行需要多核 CPU。

创建线程 —— 三种姿势，任你挑选

头文件 #include <thread> 编译参数 g++ -std=c++11 test.cpp

方式一：传函数指针 —— 最经典 
#include <iostream>
#include <thread>

void printMessage(int count) {
    for (int i = 0; i < count; ++i) {
        std::cout << "线程: 你好！👋\n";
    }
}

int main() {
    // 创建线程：把函数和参数传进去
    std::thread t1(printMessage, 5);
    t1.join();  // 等待线程干完活再继续
    return 0;
}
▶ 输出结果
线程: 你好！👋 线程: 你好！👋 线程: 你好！👋 线程: 你好！👋 线程: 你好！👋
方式二：传函数对象 —— 面向对象玩家最爱 
#include <iostream>
#include <thread>

class PrintTask {
public:
    // 重载 operator() —— 让对象像函数一样被调用
    void operator()(int count) const {
        for (int i = 0; i < count; ++i) {
            std::cout << "线程: 函数对象在工作！📦\n";
        }
    }
};

int main() {
    std::thread t2(PrintTask(), 5);
    t2.join();
    return 0;
}
方式三：Lambda 表达式 —— 现代 C++ 首选 ✨ 
#include <iostream>
#include <thread>

int main() {
    // Lambda 直接内联写在线程里，简洁优雅！
    std::thread t3([](int count) {
        for (int i = 0; i < count; ++i) {
            std::cout << "线程: Lambda 起飞！⚡\n";
        }
    }, 5);

    t3.join();
    return 0;
}
🌟 推荐：日常开发优先用 Lambda 表达式——代码紧凑、逻辑内聚，不需要额外定义函数或类。

线程管理 —— join() 与 detach() 的抉择

🤝 join() —— "我等你"

主线程调用 t.join() 后会阻塞等待，直到线程 t 执行完毕。

🖼️ 想象：你和朋友约好一起走，你在门口等他收拾完。

std::thread t(task);
t.join();   // 阻塞，等 t 执行完
// t 结束后才执行到这里

🕊️ detach() —— "你先走吧"

调用 t.detach() 后线程独立运行于后台，主线程不再管它。

🖼️ 想象：你让快递员自己去送货，你继续做别的事。

std::thread t(task);
t.detach(); // 线程分离，后台运行
// 主线程立即继续，不等待 t
⚠️ 警告：如果线程对象销毁前既没有调用 join() 也没有调用 detach()， 程序会直接崩溃（std::terminate）！这是新手最容易犯的错误。

线程传参 —— 值传递 vs 引用传递

📋 默认是值传递（拷贝）

线程默认会拷贝一份参数传给线程函数，即使原函数签名用的是引用。这是为了防止主线程中的变量被销毁后，子线程访问悬空引用。

std::thread t(func, arg1, arg2);  // arg1, arg2 会被拷贝！

🔗 如需引用传递：用 std::ref()

如果确实想让线程修改外部变量，需要用 std::ref() 包装一下：

引用传参示例 
#include <iostream>
#include <thread>

void increment(int& x) { ++x; }  // 参数是引用

int main() {
    int num = 0;
    std::thread t(increment, std::ref(num));  // ← 关键！
    t.join();
    std::cout << num;  // 输出 1 ✅ 主线程的 num 被修改了
    return 0;
}

线程同步与互斥 —— 别让线程"打架"

多个线程共享数据时如果没有保护，就会出现数据竞争 (Data Race)—— 就像两个人同时在一张纸上写字，结果谁也看不清写了什么。 下面四种武器帮你解决这个问题：

🔒 武器一：互斥量 Mutex —— "排队上厕所"

简单粗暴：谁先锁上谁先用，其他人门口等着。

#include <mutex>

std::mutex mtx;  // 全局锁

void safeWrite() {
    mtx.lock();      // 🔐 上锁
    // ... 安全地操作共享数据 ...
    mtx.unlock();    // 🔓 解锁（千万别忘了！）
}
⚠️ 陷阱：如果 lock() 和 unlock() 之间的代码抛异常， unlock 永远不会执行 → 死锁。所以更推荐下面两种…

🗝️ 武器二：lock_guard & unique_lock —— "自动锁"

RAII 机制：构造时自动上锁，析构时自动解锁。绝不漏锁。

void safeWriteGuard() {
    std::lock_guard<std::mutex> lk(mtx);  // 自动上锁
    // ... 安全操作 ...
}  // ← 离开作用域，自动解锁！

void safeWriteUnique() {
    std::unique_lock<std::mutex> ul(mtx);
    // ... 安全操作 ...
    ul.unlock();  // unique_lock 还支持手动解锁！
    // ... 做点不用锁的事 ...
}
特性 lock_guard unique_lock
自动解锁 ✅ ✅
手动解锁 ❌ ✅
转移所有权 ❌ ✅
配合条件变量 ❌ ✅
性能开销 低 略高

📡 武器三：条件变量 Condition Variable —— "传呼机模式"

生产者/消费者经典场景：一个线程说"数据准备好了"，另一个线程收到通知才开始干活。 避免了忙等待（busy-wait），CPU 不用空转。

😴
工作线程
cv.wait() 等待
→
📢
主线程
cv.notify_one() 通知
→
🏃
工作线程
被唤醒，干活！
#include <mutex>
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;  // 条件标志

void worker() {
    std::unique_lock<std::mutex> lk(mtx);
    cv.wait(lk, []{ return ready; });  // 等！直到 ready==true
    // 被唤醒，继续工作 🎉
}

void boss() {
    {
        std::lock_guard<std::mutex> lk(mtx);
        ready = true;  // 数据准备好了
    }  // 解锁
    cv.notify_one();  // 📢 "起床干活了！"
}

⚛️ 武器四：原子操作 Atomic —— "最小的不可分割单元"

对于简单的计数器场景，用 mutex 太重了。std::atomic 利用 CPU 硬件指令保证操作不可分割， 无需加锁，性能极高。 

#include <atomic>

std::atomic<int> counter(0);

void increment() {
    counter.fetch_add(1);  // 原子+1，线程安全的！
    // 等价于 counter++，但 counter++ 不是原子的！
}
💡 简单选择法：简单计数 → std::atomic；复杂共享数据 → std::mutex。

综合实战 —— 三个线程并发运行

以下演示如何用三种不同方式创建三个线程，让它们并发执行：

完整示例：三种方式 + 线程管理 
#include <iostream>
#include <thread>
using namespace std;

// 方式一：普通函数
void foo(int Z) {
    for (int i = 0; i < Z; i++)
        cout << "🔧 函数指针方式\n";
}

// 方式二：函数对象类
class ThreadObj {
public:
    void operator()(int x) const {
        for (int i = 0; i < x; i++)
            cout << "📦 函数对象方式\n";
    }
};

int main() {
    cout << "🚀 三个线程独立运行！\n";

    thread th1(foo, 3);                     // 函数指针
    thread th2(ThreadObj(), 3);            // 函数对象
    thread th3([](int x) {                  // Lambda
        for (int i = 0; i < x; i++)
            cout << "⚡ Lambda 方式\n";
    }, 3);

    th1.join();  // 等三个线程都完成
    th2.join();
    th3.join();

    return 0;
}
🎲 注意：由于线程调度由操作系统决定，每次运行的输出顺序可能不同。 三个线程的输出会交错出现——这正是并发的魅力（也是复杂性的来源）！

进阶话题：TLS 线程局部存储 & 死锁预防

🧩 thread_local —— "每人一份"

用 thread_local 关键字声明的变量，每个线程都有自己独立的一份拷贝。天然线程安全，无需加锁。

thread_local int myData = 0;

void worker() {
    myData = 42;  // 只改自己的，不影响别人
}

💀 死锁 Deadlock —— "互相等待的僵局"

线程 A 持有锁1等锁2，线程 B 持有锁2等锁1——谁也动不了。

🛡️ 破解三招：

  • 🔢 总是按相同顺序获取锁
  • ⏱️ 使用 超时锁（try_lock_for）
  • 🔍 使用死锁检测算法

线程间通信 —— future/promise 快递系统

📬 std::promise → std::future：线程间的"快递包裹"

promise 是"发件人"，往里面塞值； future 是"收件箱"，从中取值。完美的线程间值传递！

📮
promise
set_value(10)
→
📬

std::promise<int> p;
std::future<int> f = p.get_future();

std::thread t([&p] {
    // 做一些计算...
    p.set_value(42);  // 📮 快递发出！

int result = f.get();   // 📬 收到快递！result = 42

C++17 彩蛋 —— 并行算法，一行代码用满多核

C++17 在 <algorithm> 中引入了执行策略，让你一行代码就享受多核并行：

#include <algorithm>
#include <vector>
#include <execution>

std::vector<int> vec = {1, 2, 3, 4, 5};

// par = parallel，自动并行执行！
std::for_each(std::execution::par,
    vec.begin(), vec.end(),
    [](int& n) { n *= 2; }
);
📦 三种执行策略： seq（顺序）、 par（并行）、 par_unseq（并行+向量化）。 适用于 for_each、sort、transform、reduce 等算法。
