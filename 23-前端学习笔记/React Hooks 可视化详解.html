⚛️ React Hooks 可视化详解

useState · useEffect · useRef · 规则 · 闭包 · Class vs Hooks

① Hooks 解决了什么问题 Why Hooks?

❌ 以前：Class 组件

// this 满天飞，逻辑散落在各个生命周期
class Counter extends React.Component {
  constructor(props) {
    super(props)
    this.state = { count: 0 }
  }

  componentDidMount() { /* 初始化 */ }
  componentDidUpdate() { /* 更新 */ }
  componentWillUnmount() { /* 清理 */ }

  render() {
    return <button onClick={this.handleClick}>
      {this.state.count}
    </button>
  }
}

✅ 现在：Hooks 函数组件

// 没有 this，没有 class，只有函数 + Hook
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    document.title = `点了 ${count} 次`
  })

  return <button onClick={() => setCount(count + 1)}>
    {count}
  </button>
}
🎯 Hooks 的目标：让函数组件也能用 state 和生命周期，消灭 this，让逻辑复用从"套娃"变"函数调用"。

② useState — 让函数有"记忆" 核心

function Counter() {
  const [count, setCount] = useState(0)
  // ↑ 当前值 ↑ 修改函数 ↑ 初始值

  return (
    <div>
      <p>你点了 {count} 次</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  )
}
第一次渲染
count=0
→
点按钮
setCount(1)
→
重新渲染
count=1
🔒 闭包机制：每次渲染，count 都是该次渲染的快照。 setCount 更新后触发重新渲染，新闭包捕获新值。

③ useEffect — 处理副作用 生命周期终结者

// 组件挂载时或 userId 变化时执行
useEffect(() => {
  fetch(`/api/user/${userId}`)
    .then(res => res.json())
    .then(data => setUser(data))

  // 返回"清理函数"
  return () => {
    console.log('清理，比如取消订阅')
  }
}, [userId]) // ← 依赖数组

🔄 每次都执行

useEffect(() => {
  // 每次渲染后都执行
})

🚀 只挂载一次

useEffect(() => {
  // 组件挂载时执行一次
}, [])
空数组 = 没有依赖，永远不会重新执行

🎯 依赖变化才执行

useEffect(() => {
  // userId 变了才执行
}, [userId])

🧹 带清理的版本

useEffect(() => {
  const handler = () => console.log('resize')
  window.addEventListener('resize', handler)

  return () => {// 清理函数
    window.removeEventListener('resize', handler)
  }
}, [])
清理函数何时执行？
① 组件卸载时 ② 下次 effect 执行前（清理旧的，再跑新的）

④ useRef — 可变容器，不改不渲染 引用

function Timer() {
  const timerRef = useRef(null)

  const start = () => {
    timerRef.current = setInterval(() => {
      console.log('tick')
    }, 1000)
  }

  return (
    <div>
      <button onClick={start}>开始</button>
      <button onClick={stop}>停止</button>
    </div>
  )
}
useState vs useRef

改值触发重新渲染useState ✅
改值不触发重新渲染useRef ✅
存定时器 IDuseRef ✅
获取 DOM 节点useRef ✅

⑤ 自定义 Hook — 逻辑复用的终极方案 Reusable

📦 定义：把逻辑打成包

// 这是一个自定义 Hook（函数名以 use 开头）
function useWindowWidth() {
  const [width, setWidth] = useState(
    window.innerWidth
  )

  useEffect(() => {
    const handler = () =>
      setWidth(window.innerWidth)
    window.addEventListener(
      'resize', handler
    )
    return () => window.removeEventListener(
      'resize', handler
    )
  }, [])

  return width
}

🔌 使用：哪里需要哪里拿

// 任意组件直接使用，不需要 class/HOC
function MyComponent() {
  const width = useWindowWidth()

  return (
    <p>窗口宽度：{width}px</p>
  )
}

// 另一个组件也能用
function Sidebar() {
  const width = useWindowWidth()
  const collapsed = width < 768
  // ...
}
🧠 本质：自定义 Hook 就是一个函数，内部可以调用其他 Hook（useState、useEffect 等）。 它和普通函数的区别仅在于名字以 use 开头——React 靠这个约定来检查 Hook 规则。

场景 以前 Class 现在 Hooks

更新状态 this.setState({count: 1}) setCount(1)

this 问题 经常绑错 this 没有 this

⑦ Hooks 的两条铁律 Rules

1
只在最顶层调用
不要在条件、循环、嵌套函数里用 Hook。
React 靠调用顺序匹配每次渲染的 Hook。
2
只在 React 函数里调用
普通 JS 函数不能用 Hook。
只能在函数组件或自定义 Hook 里调用。
❌ 错误写法：
if (isLoading) {
  const [data] = useState(null)  // ❌ 条件里不能调用 Hook
}
✅ 正确写法：始终在最顶层调用，条件判断放里面

⑧ 闭包 × Hooks — 底层原理 Under The Hood

💡 Hooks 底层大量依赖闭包。
每次渲染都是一个独立的闭包，useEffect 捕获的是"那一次"渲染的变量值。

🔒 每次渲染 = 新的闭包

function Counter() {
  const [count, setCount] = useState(0)

  const handleClick = () => {
    setTimeout(() => {
      alert(count)  // ← 这个 count 是点击时的快照
    }, 3000)
  }

  return (
    <button onClick={handleClick}>
      {count}
    </button>
  )
}
渲染 #1: count=0, handleClick 闭包捕获 0
↓ 点击按钮 → setTimeout(3秒)
渲染 #2: count=1（setCount 触发了重渲染）
↓ 3秒到
alert(0) ← 弹出的是渲染#1捕获的值，不是当前值
闭包陷阱：setTimeout 的回调捕获了"那一次"渲染的 count。 为了解决这个问题，setCount 可以传函数：setCount(prev => prev + 1)
