# 幂等（Idempotent）是什么意思？

> **同一个操作做一次和做一百次，结果是一样的** —— 这就是幂等。

---

## 现实例子

### ✅ 幂等的
- **把电视机音量设为 15** — 按一次到 15，按一百次还是 15（结果不变）
- **删掉 id=5 的文章** — 第一次删掉了，第二次说"已删除"，结果都是没了
- **把密码改成"123"** — 改一次是这个密码，改一百次还是这个密码

### ❌ 不幂等的
- **音量 +1** — 按一次 11，按两次 12，结果每次都变
- **发布新文章** — 点一次发一篇，点两次发两篇（重复提交灾难）
- **银行转账 +100** — 点一次扣 100，点两次扣 200

---

## HTTP 方法回头看

```
GET     /api/users/1      ✅ 幂等 — 查一万次，结果都一样
PUT     /api/users/1      ✅ 幂等 — 设成 {name:"小夏"} 一百次，结果还是 {name:"小夏"}
DELETE  /api/users/1      ✅ 幂等 — 删一次没了，删一百次还是没了

POST    /api/users        ❌ 不幂等 — 发一次新增一个用户，发两次新增两个
PATCH   /api/users/1      ❌ 不严格幂等 — 取决于具体怎么用
```

### PATCH 为什么不幂等？

```http
PATCH /api/users/1
{"count": "count + 1"}     ← 每次 +1，就不幂等了
```

但如果 PATCH 是 `{"count": 5}`（直接设死值），那它又是幂等的。所以 PATCH **本身不保证**幂等。

---

## 为什么幂等重要？

### 1. 防止重复提交
点下单按钮，网络卡了又点了一下 —— 不幂等会扣两次钱，幂等的会识别并忽略第二次。

### 2. 网络重试安全
请求超时但服务器其实已处理，客户端重试：
- **幂等操作：** 重试没问题
- **不幂等操作：** 重复执行就出 bug

### 3. 日志和调试
同样的请求发多次，幂等的接口不会搞乱数据。

---

## 前端最常见的幂等问题：表单重复提交

```js
// ❌ 用户狂点提交按钮 → 发了 N 个 POST
submitBtn.addEventListener('click', async () => {
  await fetch('/api/order', { method: 'POST', body: ... })
})

// ✅ 修复：点完禁用按钮
submitBtn.addEventListener('click', async () => {
  submitBtn.disabled = true    // 点完变灰，点不了第二次
  await fetch('/api/order', { method: 'POST', body: ... })
})
```

---

## 一句话总结

> **幂等 = 重复做不会出事。** GET 和 PUT 天然安全（查多少次都一样），POST 天然不安全（每发一次多一条数据），所以下单、注册这类操作要在代码里防重复。
