🎯 导航的本质：从 A 到 B，别撞墙

🚗
导航 = 规划 + 控制

想象你开着车去一个陌生的地方。你先在导航APP上输入目的地（目标设定）， 导航帮你规划一条避开拥堵的路线（全局规划）， 然后你实际开车时要随时注意前方行人、变道车辆、红绿灯（局部避障）， 同时还要保持在车道内行驶（控制）。

🔑 对机器人来说，导航有三件大事：
1️⃣ 全局规划 —— 从地图上找一条从起点到终点的最优路径（不撞已知障碍物）
2️⃣ 局部控制 —— 实时避开突然出现的障碍物（如跑过去的人、椅子）
3️⃣ 定位 —— 时刻知道"我现在到底在地图里的哪个位置"

🗂️ 核心概念：分层代价地图

Nav2 的代价地图（Costmap）是一个分层结构，每一层管一种信息：

🔴 静态层 (Static Layer)

SLAM 建好的地图。记录已知的墙壁、柱子等固定障碍物。 一旦建好就不会变。

🟠 障碍物层 (Obstacle Layer)

传感器实时检测到的动态障碍物——桌子腿、行人、 突然出现的箱子。实时更新。

🟡 膨胀层 (Inflation Layer)

围绕每个障碍物加上一圈"安全缓冲带"。 防止机器人刮蹭到障碍物的边缘。

🟢 你的自定义层

你的地面分割模型就放在这一层——地面=自由空间， 非地面=障碍物。实时更新，替代传统激光雷达。

💡 分层的好处： 各层独立维护、独立更新。传感器换了只替换对应层， 其他层不受影响。这正是你能用"地面分割"替换"激光雷达"的关键原因—— 只需要写一个新的 Costmap Layer 插件！

🧠 双脑协作：全局规划器 + 局部控制器

🧭
全局规划器（大总管）

拿到目标后，基于静态地图计算出一条最优路径。 就像你出发前用导航APP规划好的路线——"走这条路最快"。 它不管路上突然出现的快递车。

常用算法：A* (A-Star)、Dijkstra、Smac Planner

⚡
局部控制器（急先锋）

拿着全局路径，实时根据传感器数据做微调。 前方突然有障碍物？紧急绕开。地面不平？减速通过。 就像你实际开车时随时调整方向盘、油门和刹车。

常用算法：DWB (Dynamic Window Based)、TEB、Regulated Pure Pursuit

📐 全局路径（粗粒度，约1Hz更新）

"从起点沿走廊走5米，左转进入房间，走到房间角落"

⚡ 局部速度指令（细粒度，约20-50Hz更新）

"现在往左偏2度，速度0.3m/s，避开前方30cm处的椅子腿"

🎯 为什么需要两个？ 全局规划算得准但算得慢，局部控制反应快但看得近。 两者配合：全局定方向，局部管安全。缺一个都会出事。

🏗️ Nav2 的完整架构

Nav2 采用分层架构设计，从底层到顶层共六层：

🔴 硬件接口层 —— 传感器驱动、电机驱动、底盘通信
🟠 传感器处理层 —— IMU滤波、激光雷达数据处理、地面分割推理
🟡 控制器层 —— 局部规划器（DWB/TEB）、速度平滑、里程计计算
🟢 规划器层 —— 全局规划器（A*/Smac）、行为树引擎、路径平滑
🔵 代价地图层 —— 分层代价地图管理、各层插件、坐标变换
🟣 行为层 —— 行为树编排（探索→导航→拍摄→返回）、状态监控

ROS2 的通信采用 4 种通信机制：

机制用途类比
Topic持续数据流（传感器数据、速度指令）广播电台
Service一次性请求-响应（保存地图、查询状态）打电话
Action长时间任务+可取消+进度反馈（导航到目标）外卖订单
Parameter配置参数读写（速度上限、膨胀半径）设置菜单
📌 导航最常用的是 Action： 给机器人发一个"去(x=3, y=5, 面朝北)"的导航目标，这是一个 Action。 它可以反馈进度（"走了50%了"）、可以被取消（"算了别去了"）、可以报告结果（"到了/堵死了"）。

🌳 行为树：机器人的"大脑皮层"

Nav2 使用行为树（Behavior Tree）来编排复杂的导航行为。行为树是一种树状结构，每个叶子节点是一个动作，非叶子节点是控制逻辑（顺序、选择、并行等）。

🌳 一个典型的导航行为树
  ┌──────────────── Sequence（顺序执行） ────────────────┐
  │                                                      │
  │  ├── ✓ 恢复控制器（检查机器人状态是否正常）          │
  │  ├── ✓ 获取目标位姿（从探索模块获取下一个探索点）       │
  │  ├── ✓ 重新规划检测（是否需要重新规划路径）            │
  │  │                                                   │
  │  ├── ┌── Fallback（备选方案）──┐                      │
  │  │   │  ├─ 计算全局路径 (A*)    │                      │
  │  │   │  ├─ 局部速度控制 (DWB)   │                      │
  │  │   │  └─ 尝试恢复行为        │ ← 堵住了就转圈、后退   │
  │  │   └────────────────────────┘                      │
  │  │                                                   │
  │  ├── 📸 到达检测 + 拍摄（触发你的视频采集节点）         │
  │  └── 📡 报告结果给探索模块（这个点探索完了）           │
  └──────────────────────────────────────────────────────┘
🧩 行为树的好处：把复杂的导航逻辑拆成可组合的积木块。 你可以轻松地插入自己的节点——比如"到达后旋转360°拍摄"、"如果电池低就返回充电桩"。 你的 BT_ros2 代码就是用行为树来编排探索→拍摄→返回的整个流程。

⚙️ 实际部署时你需要关心的关键参数

参数含义建议值 (室内)
robot_radius机器人底盘外接圆半径0.15~0.25m
inflation_radius障碍物膨胀半径（安全距离）0.3~0.5m
max_vel_x最大线速度0.3~0.5 m/s
max_vel_theta最大角速度0.5~1.0 rad/s
planner_frequency全局路径重规划频率1.0 Hz
controller_frequency局部控制频率20.0 Hz
goal_checker/xy_goal_tolerance到达目标的位置容差0.1~0.2m
goal_checker/yaw_goal_tolerance到达目标的角度容差0.2~0.3 rad
⚠️ 安全第一：实际部署时，先设置保守的速度（慢一点）， 膨胀半径设大一点。等整个管线跑通后再逐步放开。 机器人撞墙的代价远大于多花几分钟探索。
