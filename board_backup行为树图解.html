🧩 各节点详解

#节点名类型C++ 类作用端口（输入→输出）
1 ProcessReminders ReactiveSequence 内置 每 tick 从头遍历子节点。任何子节点 FAILURE 立即重试 —
2 ProcessOneReminder Sequence 内置 有记忆的序列。子节点全 SUCCESS 才 SUCCESS，否则从上次 RUNNING 处继续 —
3 TimeoutOrPlay Fallback 内置 二选一：超时路径（左）优先，失败才走正常播放路径（右） —
4 RepeatBranch Fallback 内置 二选一：重复类型→重排，非重复→发结束信号 —
5 HasPendingReminders Condition HasPendingReminders 扫描 JSON 数组，找 status∈{pending,sent,executing} 的项 pending_reminders
6 CheckTimeCondition Condition CheckTimeCondition 解析 ISO8601 时间，判断 now ≥ reminder_time？ reminder_time
7 CheckReminderTimeout Condition CheckReminderTimeout 判断 now > reminder_time + 900s？SUCCESS=超时 reminder_time
8 CheckPersonPresent Condition CheckPersonPresent 直读黑板 person_present，非0=有人 直读黑板（不走端口）
9 CheckRepeating Condition CheckRepeating 判断 repeat_type 是否不等于 "none" repeat_type
10 LoadNextReminder SyncAction LoadNextReminder 从队列取时间最早的一条，写入黑板各字段。不修改状态 pending_reminders → reminder_id,title,content,time,status,repeat_type
11 MarkStatus SyncAction MarkStatus 改 pending_reminders 中指定 reminder_id 的状态字段 pending_reminders,reminder_id,new_status
12 ReportStatus SyncAction ReportStatus 发布 reminder_response 到 /reminder/ws/result reminder_id,report_status
13 BuildReminderTts SyncAction BuildReminderTts 拼"叮咚,提醒时间到啦,{title},{content},别忘了哦!" reminder_title,content → tts_text
14 PlayReminderAudio StatefulAction PlayReminderAudio 异步生成 shell 脚本 → ros2 action send_goal /voice/speak tts_text
15 PublishResponse SyncAction PublishResponse 发布 JSON 到 /robot/command_response reminder_id,reminder_status
16 RescheduleRepeating SyncAction RescheduleRepeating daily→+1d, weekly→+7d, monthly→+30d, status→sent pending_reminders,reminder_id,reminder_time,repeat_type

⚖️ board_backup vs board_package_v2 对比

✅ board_backup（旧版，17 节点）

  • ✅ CheckReminderTimeout — 900s 超时检测
  • ✅ TimeoutOrPlay — Fallback 双路径
  • ✅ CheckRepeating — 重复类型判断
  • ✅ RescheduleRepeating — 重排时间
  • ✅ RepeatBranch — 重复/非重复分支
  • 🟢 失败后能自动跳出（超时→failed）

❌ board_package_v2（新版，11 节点）

  • ❌ 无超时检测
  • ❌ 纯线性 Sequence，无 Fallback 分支
  • ❌ 无重复判断
  • ❌ 无重排逻辑
  • ❌ 无分支
  • 🔴 PlayReminderAudio 失败后永久卡死

🔑 卡死的根本原因

board_package_v2 被卡住的三个必要条件：

  1. ❌ PlayReminderAudio 调用 TTS 失败 → exit=6
  2. ❌ 没有 CheckReminderTimeout → 无超时逃生路径
  3. ❌ 没有 Fallback 分支 → 失败后 Sequence FAILURE → ReactiveSequence 重试 → 死循环

board_backup 的应对：

  • ✅ Fallback 优先尝试 TimeoutPath → 未超时 → 走 NormalPlayPath
  • ✅ NormalPlayPath 失败 → Sequence FAILURE → ReactiveSequence 重试 → 再次进入 Fallback
  • ✅ 直到超时 → TimeoutPath 标记 failed → 跳出循环
